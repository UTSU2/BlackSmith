# V2 — 개발 계획

> **상태: 확정.** v2의 **주 목적은 숙련도로 반복 제작의 피로를 완화**하는 것이다. 아래 **[미정]** 항목은 임의로 정하지 않는다.

## 1. 순서 [확정]

1. 튜토리얼 ([Tutorial.md](Tutorial.md))
2. 숙련도 + 제작 기록 화면 (§2)
3. 적중 이펙트
4. 장비 강화
5. 정밀 밸런스 조정 (숙련도 보너스, 강화 수치, 가격 공식이 확정된 뒤 마지막에)

- 숙련도와 강화는 둘 다 세이브 구조를 건드리므로 따로 진행해 세이브 호환 문제가 겹치지 않게 한다.
- 레시피 해금은 v2 범위에 넣지 않는다. 도입 여부는 계속 **[미정]**이며, 아래 제작 기록은 해금이 아니라 **발견 기록**이다.

## 2. 숙련도 [확정된 결정]

- **대상: 레시피별.** 제작 시 매칭된 레시피가 숙련도의 대상이다. 같은 완성품을 만드는 레시피도 별개로 쌓인다. (완성품 16종에 레시피 49개)
- **효과: 품질 보너스.** 숙련도 레벨에 따라 총점(0~40)에 보너스를 더한다. 보너스는 **상한을 두어 숙련도만으로는 최상품(40)에 도달하지 못하게** 한다. 즉 숙련도로는 상품(30~39)까지만 올라가고, 최상품은 직접 만점 플레이가 필요하다. 최상품이 도전 과제로 남고 가격 구조(최상품 ×2)가 유지된다.
- **성장: 품질에 따라 쌓인다.** **중품(20점) 미만이면 쌓이지 않고, 중품 이상일 때만 쌓인다.** 품질이 높을수록 더 쌓일지, 중품 이상은 동일하게 쌓일지는 **[미정]**.
- **기록 화면(제작 기록).** 한 번 이상 제작한 레시피만 목록에 올라간다. 항목은 **완성품 이름 + 정식 레시피의 재료 구성 + 숙련도 레벨**이며, 플레이어가 넣은 재료가 아니라 매칭된 정식 레시피를 보여 준다. 재료를 조금 틀리게 넣어도 정식 레시피가 기록되므로 실험이 발견 수단이 된다.
- **기록 시점: 제작 완료 시.** 품질이 최하품이어도 기록되고 숙련도는 0으로 시작한다.
- **변화 표시.** 제작이 끝날 때 결과 팝업에 숙련도 변화를 간단히 표시한다. (예: 철검 숙련도 Lv.3 (+1))
- 아래는 **[미정]**: 레벨 수, 레벨별 필요 수치, 보너스 크기와 상한 값, 품질별 가중치, 기록 화면의 UI.

### 구조 메모
- 정적 데이터와 런타임 상태 분리: 숙련도는 `PlayerData` 쪽 런타임 상태로 두고(레시피 id → 수치), 레벨별 수치·보너스는 ScriptableObject 데이터로 둔다.
- 보너스 적용 위치는 `CraftScoring`의 총점 계산이다. 적용 후 품질 구간 경계(버림)는 그대로 쓴다.
- 세이브: `SaveFile`에 숙련도·발견 목록을 추가한다. 필드가 없는 옛 세이브는 빈 값으로 읽는다.
- 이 기능은 `GameDesign.md`·`CoreLoop.md`의 "레시피는 플레이어에게 보이지 않는다"와 충돌하므로, 구현 시 해당 문서와 `CLAUDE.md`를 "발견한 레시피만 기록 화면에 표시"로 갱신한다.

## 3. 다른 항목 [미정 많음]

| 항목 | 정해진 것 | 미정 |
|---|---|---|
| 적중 이펙트 | v2로 분리됨 | 연출 범위 |
| 장비 강화 | 강화 수치가 판매가에 반영됨 | 방식, 실패 여부, 비용, 가격 공식 |
| 정밀 밸런스 | 마지막에 진행 | 조정 기준 |

- 강화는 개별 장비 상태이므로 `ItemVariant`에 강화 수치를 추가하는 구조가 된다. 세부는 강화 단계에 들어갈 때 따로 설계한다.

## 4. 리스크

- 숙련도 보너스와 강화가 둘 다 가격에 영향을 주므로, 최상품·고강화 조합의 수익이 과도해지지 않게 마지막 밸런스 단계에서 함께 본다.
- 세이브 호환: 새 필드는 모두 "없으면 기본값"으로 읽는다.
