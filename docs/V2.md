## 1. 순서 [확정]

1. 튜토리얼 ([Tutorial.md](Tutorial.md)) — 구현 완료 (단계·조작 안내 문구는 사용자 작성 완료. 미니게임 조작 안내는 튜토리얼 제작 중 왼쪽 상단에 구현. 설정 확인 문구·팝업 디자인은 임시값)
2. 숙련도 (§2, 도감·확인 화면 제외) — 구현 완료 (결과 팝업 디자인은 임시값/미정, 튜토리얼 숙련도 문구는 사용자 작성 완료. 팝업 배치 원칙은 확정)
3. 적중 이펙트 (§4) — 구현 완료 (현재 수치로 확정)
4. 레시피 습득 — 레시피 도감, 정확 일치 매칭, 알 수 없는 제작품 (§3) — 구현 완료 (알 수 없는 제작품 아이콘, 도감 비주얼은 미정, 도감 번호는 임시값)
5. 정밀 밸런스 조정 (§5 "정밀 밸런스") — 구현 완료 (상품 이상 등급 배율, 광물 가격 인상)

- 문서에서 "레시피 해금"으로 불리던 항목은 "레시피 습득"으로 통일했다. (도감 항목의 "해금"은 도감에 올라가는 것을 뜻한다.)

## 2. 숙련도 [확정된 결정, 구현 완료]

구현: `Assets/Scripts/Proficiency`(`ProficiencySettings` 에셋 `Resources/Proficiency/ProficiencySettings.asset`, `ProficiencyRules`, `ProficiencyState`), `PlayerData.proficiencies`(`ProficiencyEntry`: 레시피 id, 누적 수치), `CraftingController.GrantResult`(보너스 적용·획득), `CraftResultPopup`(Game 씬). 아래 수치는 모두 설정 에셋 값이다.

- **대상: 레시피별.** 제작 시 매칭된 레시피가 숙련도의 대상이다. 같은 완성품을 만드는 레시피도 별개로 쌓인다. (완성품 16종에 레시피 49개)
- **효과: 품질 보너스.** 숙련도 레벨에 따라 총점(0~40)에 보너스를 더한다. 보너스는 **상한을 두어 숙련도만으로는 최상품(40)에 도달하지 못하게** 한다. 즉 숙련도로는 상품(30~39)까지만 올라가고, 최상품은 직접 만점 플레이가 필요하다. 최상품이 도전 과제로 남고 가격 구조(최상품 ×2)가 유지된다.
- **성장: 제작 총점만큼 쌓인다.** [확정] 획득량은 **보너스 적용 전 총점을 버림한 정수(0~40)**이다. **20점(중품) 미만이면 쌓이지 않는다.** 보너스 적용 전 총점이 정확히 **40점(최상품)이면 1.5배인 60점**을 얻는다. (39점 이하는 총점 그대로) 보너스 적용 후 점수를 기준으로 하면 숙련도가 높을수록 더 빨리 쌓이는 되먹임이 생기므로 쓰지 않는다.
- **단계와 레벨.** [확정] 단계는 **초급 → 중급 → 고급**이고 각 단계는 Lv1~9(총 27레벨)다. 고급 Lv9를 채우면 **Master**이며 더 쌓이지 않는다. 표기는 "초급 Lv.3", "Master" 같은 문구로 한다.
- **레벨별 필요 수치.** [확정] 레벨을 오를 때 필요한 수치다.
  - Common 초급 Lv1 = **100**. 같은 단계 안에서는 레벨마다 **×1.2**.
  - 단계가 넘어갈 때(Lv9 → 다음 단계 Lv1)는 **초급→중급 ×1.5, 중급→고급 ×1.5**.
  - 등급이 오를 때마다 **Lv1 시작 수치에 +50** (Uncommon 150, Rare 200, Unique 250, Legendary 300). 이후 배율은 같으므로 모든 값이 시작 수치에 비례한다. 등급은 **레시피 결과물의 등급**이다.
  - 수치는 반올림하지 않은 값으로 이어 계산하고, 레벨별 필요 수치는 **half-up 반올림한 정수**(`PriceRounding`과 같은 규칙)로 쓴다.
  - Common 값: 초급 100, 120, 144, 173, 207, 249, 299, 358, 430 / 중급 645, 774, 929, 1115, 1337, 1605, 1926, 2311, 2773 / 고급 4160, 4992, 5990, 7188, 8626, 10351, 12421, 14906, 17887. Master까지 합계 102,016.
- **이월.** [확정] 필요 수치를 넘긴 분량은 다음 레벨로 이월한다. 단계가 넘어갈 때도 같다. Master 총량을 넘는 분량은 버린다. 필요 수치(최소 100)가 한 번의 최대 획득량(60)보다 커서 한 번에 두 레벨 이상 오르지는 않는다.
- **보너스.** [확정] 레벨마다 **0.1점**씩 늘어(초급 Lv2 0.2 … 고급 Lv9(Lv27) 2.7) Master에서는 **총 3.0점**이다. **초급 Lv1은 보너스가 없다(0).** [확정, 2026-11-17] 다른 레벨 값은 그대로라 초급 Lv1 → Lv2에서 0 → 0.2로 오른다. 총점(0~40)에 더한다. **보너스 적용 전 총점이 40 미만일 때 보너스를 더해 39 이상이 되면 39로 맞춘다.** [확정] 최상품(40)은 **보너스 없이 직접 40점**을 얻어야만 나온다. (보너스 적용 전 총점이 40이면 보너스를 더하지 않는다.)
- **제작 횟수 참고** (총점 평균 30일 때, 전체 단계, 평균 20점이면 약 1.5배, 전부 최상품(획득 60)이면 약 0.5배): Common 약 3,400회, Uncommon 약 5,100회, Rare 약 6,800회, Unique 약 8,500회, Legendary 약 10,200회. 고급 단계 한 곳만 보면 Common 약 2,885회에서 Legendary 약 8,650회다.
- **제작 결과 팝업.** [확정] 지금(v1)은 제작 결과 팝업이 없다(완성품은 인벤토리에 들어가고 로그만 남는다). 이 단계에서 **결과 팝업을 새로 만들고 확인 버튼으로 닫는다.**
  - 표시 내용: **완성품 이름·등급·품질**, **숙련도 단계·레벨**, **이번 획득량**, **진행도(숫자 + 게이지, 예: 85 / 144)**, **품질 보너스 점수**(예: +0.3). 예: "철검 (Common) 상품 / 초급 Lv.3 (+32) / [게이지] 85 / 144 / 품질 보너스 +0.3"
  - 20점 미만이라 쌓이지 않았거나 이미 Master이면 **현재 단계·레벨만 표시**한다. (예: "초급 Lv.3", "Master")
  - 레벨업, 단계 상승, Master 도달은 **따로 강조하지 않는다.**
  - 표시하는 보너스는 현재 레벨의 보너스 값이다. 39 상한으로 실제 더해진 양이 줄어도 레벨 값 그대로 보여 준다. (제안)
  - **배치.** [확정] 완성품 **아이콘을 좌측 상단**에 두고 아이콘 위쪽을 아이템명 위쪽에 맞춘다. 아이템명은 **상단 중앙**이다. 긴 이름이 2줄이 되지 않도록 **이름과 등급·품질을 두 줄로 나눈다**(예: "철검" / "(Common) 상품"). 글자와 아이콘·버튼이 서로 겹치지 않고 팝업 밖으로 나가지 않게 한다. 아이콘은 글자와 겹치지 않는 한 최대한 오른쪽에 둔다.
  - 현재 수치(임시, 팝업 상자 위쪽 기준 px): 상자 700×440(레시피 습득에서 해금 줄을 넣으며 390에서 늘림). 아이콘 100×100, 가로 90~190, 위 25. 이름 줄(글자 34) 위 25~75, 등급·품질 줄(글자 28) 위 80~120, 두 줄 모두 가로 200~500(폭 300). 해금 줄(처음 만든 레시피만) 135~179, 숙련도 185~229(알 수 없는 제작품이면 같은 자리에 판매가), 진행도 게이지 240~280, 품질 보너스 290~330, 확인 버튼 아래 여백 20(225×75). 이름 폭 300은 현재 가장 긴 이름(사파이어 전투도끼, 284)에 맞춘 값이라 더 긴 이름을 추가하면 아이콘을 왼쪽으로 옮기고(최대 가로 10) 폭을 넓힌다.
- **튜토리얼.** [확정] 튜토리얼의 철검 제작도 숙련도에 쌓인다. 튜토리얼 문구에 숙련도가 오른다는 내용을 추가한다(문구 내용은 **[미정]**).
  - **숙련도 안내 시점** [확정, 2026-11-17]: 제작이 끝나 **결과(숙련도) 팝업이 뜨는 것과 동시에** 숙련도 안내 문구가 **화면 상단** 튜토리얼 팝업으로 나온다. 결과 팝업의 **확인을 누르면** 지금의 `Step_04` 문구(제작법 설명)로 넘어간다. 안내 팝업에는 확인 버튼이 없고, 결과 팝업의 확인으로만 넘어간다. (구현됨: 단계 에셋 `Step_03_Proficiency`, 조건 `CraftResultClosed`. 문구는 `[임시]`)
- **숙련도 확인 화면은 이 단계에서 만들지 않는다.** [확정] 숙련도 확인은 4번의 레시피 도감에서 한다. 이 단계에서는 숙련도 수치를 저장하고 결과 팝업의 표시만 둔다.
- 알 수 없는 제작품(§3)은 레시피가 없으므로 숙련도가 없다.
- 아래는 **[미정]**: 결과 팝업의 디자인(스프라이트·색·글꼴, 위 배치 원칙 밖의 세부 수치), 숙련도 안내 튜토리얼 문구의 내용(시점·위치는 확정).

### 구조 메모
- 정적 데이터와 런타임 상태 분리: 숙련도는 `PlayerData` 쪽 런타임 상태로 두고(레시피 id → **누적 숙련도 정수 한 개**), 레벨은 필요 수치표의 누적 합으로 계산한다. 이월이 따로 필요 없다. 시작 수치·배율·보너스 값은 ScriptableObject 데이터로 둔다.
- 보너스 적용 위치는 `CraftScoring`의 총점 계산이다. 적용 후 품질 구간 경계(버림)는 그대로 쓴다.
- 결과 팝업은 `BlackSmith.UI`에 두고 `CraftingController.CraftFinished`를 듣고 표시한다. 확인 버튼은 `ButtonLabelPress`를 붙인다. 튜토리얼은 결과 팝업이 닫힌 뒤에 `Step_04`로 넘어가야 하므로 `TutorialFlow`/`TutorialController`에 대기 조건이 필요하다.
- 세이브: `SaveFile`에 숙련도를 추가한다. 필드가 없는 옛 세이브는 빈 값으로 읽는다. (도감 해금 목록은 4번에서 추가한다.)

## 3. 레시피 습득 [확정된 결정, 구현 완료]

설계: [superpowers/specs/2026-11-18-recipe-acquisition-design.md](superpowers/specs/2026-11-18-recipe-acquisition-design.md). v1의 "가장 가까운 레시피를 자동 선택하고 레시피 북은 비공개"를 아래로 바꿨다.

구현: `RecipeMatcher`(정확 일치), `UnknownCraftSettings`(에셋 `Resources/Crafting/UnknownCraftSettings.asset`), 아이템 `Resources/Items/Crafted/999.asset`(`CraftedItemData.fixedSellPrice` 50), `CraftRequest`(레시피가 없으면 `IsUnknown`), `CraftRecipeData.codexNumber`·`RecipeCodex`, `PlayerData.unlockedRecipes`·`codexInitialized`, `CraftResult.NewlyUnlocked`, `CodexPanel`·`CodexSlotView`(Game 씬), `GameHUD.OnCodex`.

**방향 [확정, 2026-11-18]**
- **재료를 넣어 보는 실험 자체가 재미다.** 새 레시피는 플레이어가 재료 조합을 직접 시도해 찾는다(단서 제공 없음). 제작 패널은 재료가 하나 이상이면 레시피 여부와 관계없이 같은 문구("제작할 수 있습니다")와 같은 시작 버튼을 보여 준다.
- **레시피는 현재 49종으로 v2 완성**으로 본다. 재료 구성 수정으로 하는 밸런스 조정은 **v3**에서 한다. (도감 해금은 레시피 id 기준이므로 v3에서 구성이 바뀌어도 해금 기록은 유지된다. 레시피 **id를 바꾸면** 해금·숙련도 기록이 끊긴다 — Recipe Creator가 경고한다)
- 완성품은 **알 수 없는 제작품 1종만 추가**한다(레시피에는 넣지 않음). 그 밖의 아이템·레시피는 추가하지 않는다.
- 도감을 채우는 경로는 **실험(직접 제작)뿐**이다. 상점·보상 등 다른 경로는 v2에서 만들지 않는다. [확정, 2026-11-18]

**레시피 도감**
- 저장(책) 버튼 왼쪽의 도감 버튼으로 여는 UI 패널. 튜토리얼 중에도 열린다.
- **해금 시점: 제작 완료 시.** 품질이 최하품이어도 해금되고 숙련도는 0으로 시작한다.
- **배치 [확정]:** 7×7 격자 + 오른쪽 상세. 위에 진행도 **"해금 n / 49"**와 막대(분모는 전체 레시피 수, 알 수 없는 제작품 제외).
- **모르는 칸:** 번호와 `???`만 보인다. **해금한 칸:** 완성품 아이콘(아이콘이 없는 임시 장비는 이름 첫 글자). 상세는 번호·완성품 이름·등급·**재료 구성(재료 × 수량)**·숙련도(단계·레벨, 진행 수치와 막대, 품질 보너스). 숙련도 기록이 없으면(20점 미만 제작) 초급 Lv.1, 0 / 필요 수치로 보인다.
- **순서: 도감 번호** [확정]. 레시피마다 `codexNumber`(1부터)를 두고 그 순서로 놓는다. 낮은 등급 완성품이 앞 번호다. 번호는 **Recipe Creator에서 직접 입력**하고, 창이 번호 없음·중복·등급 순서 위반을 경고한다. 해금 기록은 **레시피 id**로 저장하므로 번호가 밀려도 다른 칸이 해금되지 않는다.
- **현재 번호는 임시값**이다: 결과 등급순 → 같은 등급 안에서는 레시피 id 글자순. (Common 1–19, Uncommon 20–31, Rare 32–40, Unique 41–46, Legendary 47–49. 철검이 1번)
- **해금 알림 [확정]:** 처음 만든 레시피면 제작 결과 팝업에 **"새 레시피 해금! (No.n)"** 줄이 보인다(상자 높이 440, 등급·품질 줄 아래).
- **기존 저장 데이터** [확정, 2026-11-18]: 도감이 생기기 전의 저장 파일은 불러올 때 한 번, **저장된 숙련도 기록이 있는 레시피를 해금한 것으로** 채운다(`codexInitialized`). (참고: 숙련도는 총점 20점 이상일 때만 기록되므로, 숙련도 도입 전의 제작이나 20점 미만 제작은 기록이 없어 해금되지 않는다)

**정확 일치 매칭**
- v1의 "가까운 레시피" 점수제는 폐지했고 **정확히 일치해야만** 레시피가 선택된다. [확정, 2026-11-18 재확인]
- 일치 기준은 **재료 종류 + 수량**이다. 같은 이름의 다른 등급 아이템은 없으므로 등급은 일치 여부와 무관하다.
- 투입한 재료는 지금과 같이 제작을 시작할 때 모두 소모된다.
- 재료 구성이 같은 레시피가 둘이면 먼저 등록된 것이 쓰이고, 게임 시작 시(`RecipeDatabase`)와 Recipe Creator가 경고한다. (현재 49종에는 없음)
- 튜토리얼 철 원석 ×1 → 철검은 정확 일치라 그대로 동작한다. `Step_04`의 "가장 가까운 제작법" 문구는 사용자가 고친다.

**알 수 없는 제작품**
- 레시피가 없는 조합으로 제작하면 **"알 수 없는 제작품"**이 나온다. 이 아이템은 **레시피에 추가하지 않는다** [확정, 2026-11-18]. (콘텐츠 규칙 "모든 광물은 레시피가 하나 이상 있어야 한다"는 그대로 유지된다)
- Common 등급 완성품이며 **ID는 `999`**, 아이콘은 **[미정]**(지금은 없음). 설명 문구는 `[임시]`.
- 판매가는 **품질과 관계없이 50골드 고정**이다(`fixedSellPrice`). (가장 싼 재료도 100골드이므로 정확히 일치하지 않는 제작은 항상 손해다)
- 도감에 해금되지 않고 숙련도도 없다. 미니게임 **난이도는 2 고정**, 단계는 가열·단조·열처리·연마 4개(설정 에셋 값).
- 품질은 지금처럼 미니게임 점수로 정해지지만 가격과 숙련도에는 영향이 없다. 결과 팝업은 숙련도 줄 대신 **"판매가 50 G"**를 보여 준다.
- 설정 에셋이 없으면 레시피와 일치하는 조합만 제작할 수 있다(경고 로그, 이때만 "조합이 맞지 않습니다"가 보인다).

**[미정]**
- 알 수 없는 제작품의 아이콘, 도감 패널·도감 버튼의 최종 비주얼(지금은 임시: 양피지 패널, 초록 표지 책 아이콘), 튜토리얼 문구.

### 구조 메모
- 세이브: `PlayerData`에 `unlockedRecipes`(레시피 id 목록)와 `codexInitialized`를 추가했다. 필드가 없는 옛 세이브는 `GameSession.Set`에서 `EnsureCodexInitialized()`가 숙련도 기록으로 한 번 채운다. `SaveFile.CurrentVersion`은 1 그대로.
- 임시 레이아웃 값: 패널은 상점과 같은 크기(양피지), 칸 96px·간격 8px, 상세 726×720.

## 4. 적중 이펙트 [확정된 결정, 구현 완료]

설계: [superpowers/specs/2026-11-17-hit-effects-design.md](superpowers/specs/2026-11-17-hit-effects-design.md). 리듬게임식 손맛을 판정 순간의 시각 연출로 보강한다.

- **대상: 단조와 연마.** [확정] 가열·열처리는 넣지 않는다.
- **단조:** [확정] 원이 판정될 때 그 원 자리에서 **금색 계열 빛**이 난다. 크기는 **Perfect > Good > 눌렀지만 Miss**. **누르지 못하고 놓친 Miss는 빛이 없다.** 원이 없는 빈 곳 클릭도 없다. 판정 정보는 기존 원 색(녹/노/빨)이 맡는다.
  - **모양: 도넛형.** [확정, 2026-11-17] 빛은 **원 바깥으로만** 퍼지고 **원은 가리지 않는다.** 링의 구멍이 판정 원(안쪽 원) 가장자리에서 시작해 바깥으로만 커지고, 불꽃도 원 가장자리 바깥에서 생긴다. 판정별 차이는 퍼지는 정도·불꽃 수·밝기로 낸다.
- **연마:** [확정] 흠집 하나를 다 지울 때마다 그 자리에서 **은색 계열 반짝임**. 모든 흠집에 같은 크기이며 **흠집 크기 정도**다(도넛 아님, 2026-11-17).
- **방식: 파티클.** [확정] 파티클이 UI 위에 보이도록 Game 씬 `GameUICanvas`를 Screen Space - Camera로 바꿨다. 이펙트는 프리팹(`Assets/Effects/ForgeHitPerfect/Good/Miss.prefab`, `PolishSparkle.prefab`)만 바꿔 교체한다. 크기는 실제 원·흠집 지름에 맞춰 자동으로 키우거나 줄인다(기준 지름 단조 160px, 연마 180px).
- **현재 값 [확정, 2026-11-17]** (아래 "수정할 수 있는 부분"에서 바꿀 수 있다):

  | 항목 | 단조 Perfect | 단조 Good | 단조 눌렀지만 Miss | 연마 |
  |---|---|---|---|---|
  | 색 | 금색 (1, 0.82, 0.35) | 금색 | 금색 | 은색 (0.85, 0.88, 0.95) |
  | 모양 | 링(도넛) + 불꽃 | 링 + 불꽃 | 링 + 불꽃 | 원형 빛 + 반짝 점 |
  | 크기 | 링 바깥 지름 512px | 432px | 368px | 빛 지름 = 흠집 지름 (×0.9 → 1.15) |
  | 링 시작 밝기 | 1.0 | 0.85 | 0.6 | 1.0 |
  | 불꽃·반짝 점 | 16개, 속도 320 | 10개, 230 | 5개, 140 | 14개, 속도 40 (흠집 안) |
  | 수명(초) | 링 0.35 / 불꽃 0.4 | 0.3 / 0.35 | 0.25 / 0.3 | 빛 0.35 / 점 0.45 |

  단조 크기는 판정 원 지름 160px, 연마는 흠집 지름 180px 기준이며 실제 원·흠집 크기에 맞춰 자동으로 키우거나 줄인다.
- **수정할 수 있는 부분** (코드 수정 없이):
  - 색·크기·밝기·개수·속도·수명: 프리팹 `Assets/Effects/ForgeHitPerfect`·`ForgeHitGood`·`ForgeHitMiss`·`PolishSparkle`의 ParticleSystem 값.
  - 이미지: 텍스처 `Assets/Effects/Textures/SoftRing.png`(단조 링), `SoftGlow.png`(빛·불꽃·연마). 재질 `HitRing.mat`, `HitEffect.mat`.
  - 판정별로 쓸 프리팹: Game 씬 `ForgePanel`의 `ForgeMinigameView`(`perfectEffect`·`goodEffect`·`missEffect`).
  - 크기 기준: 각 미니게임 화면의 `effectReferenceDiameter`(단조 160, 연마 180). 프리팹을 다른 기준 크기로 다시 만들었을 때만 바꾼다.
  - 바꿀 때 지킬 것: 단조 링은 판정 원을 가리지 않아야 한다(링 구멍 ≥ 원 지름, 크기가 줄어들지 않음, 불꽃은 원 바깥에서 생성).

### 정밀 밸런스 (v2 5번) [확정, 2026-11-18, 구현 완료]

- **문제 (v2 정밀 밸런스 이전):** 한 번 제작의 수익률이 품질로만 정해져(최하품 −30% / 하품 0 / 중품 +20% / 상품 +50% / 최상품 +100%) 등급과 관계없이 같다. 높은 등급 레시피를 찾아 만들 이유가 작다.
- **조정 기준:** 등급에 비례해 수익률을 높인다. 범위는 아래 가격 변경까지로 확정했다(숙련도 성장, 시작 자금, 제작 시간은 이번에 바꾸지 않는다).
- **완성품 등급 배율:** 품질로 계산한 판매가에 **상품 이상일 때만** 등급 배율을 곱한다. Common ×1, Uncommon ×1.1, Rare ×1.3, Unique ×1.7, Legendary ×2.5. 최하품·하품·중품에는 곱하지 않는다(저품질 양산 방지). 처음 제안은 "중품 이상"이었고 같은 날 "상품 이상"으로 바꿨다.
- **광물 구매가:** Common 100(그대로) / Uncommon 180 / Rare 350 / Unique 720 / Legendary 1200 (이전 100 / 156 / 300 / 540 / 900). 되팔기는 구매가의 절반 그대로(90 / 174 / 360 / 600. Rare는 반올림 때문에 175 대신 174).
- **결과 수익률** (구매가로 정확한 레시피 재료를 샀을 때. 판매가는 재료 등급이 아니라 완성품 등급의 배율을 쓰므로, 재료와 완성품 등급이 다른 레시피도 이 표와 같다):

  | 등급 | 최하품 | 하품 | 중품 | 상품 | 최상품 |
  |---|---|---|---|---|---|
  | Common | −30% | 0% | +20% | +50% | +100% |
  | Uncommon | −30% | 0% | +20% | +65% | +120% |
  | Rare | −30% | 0% | +20% | +95% | +160% |
  | Unique | −30% | 0% | +20% | +155% | +240% |
  | Legendary | −30% | 0% | +20% | +275% | +400% |

- **영향:** 중품(29점)과 상품(30점) 사이의 격차가 등급이 높을수록 커진다(Legendary +20% → +275%). 숙련도 보너스(최대 2.7~3점)가 상품 도달을 돕기 때문에 높은 등급에서 숙련도의 가치가 커진다. 판매가는 팔 때 계산하므로 옛 세이브의 아이템도 새 가격으로 팔린다. 튜토리얼 시작 지급금(철 원석 100)과 알 수 없는 제작품(50 고정)은 그대로다.

## 6. 리스크

- 숙련도 보너스와 레시피 습득이 둘 다 진행 속도와 수익에 영향을 줄 수 있으므로, 수익이 과도해지지 않게 마지막 밸런스 단계에서 함께 본다.
- 정확 일치로 실수한 제작의 손실이 커진다(재료 소모, 판매가 50). 튜토리얼과 도감이 이를 충분히 알려 주는지 직접 플레이로 확인한다.
- 세이브 호환: 새 필드는 모두 "없으면 기본값"으로 읽는다.
