## 2. 숙련도 [확정된 결정, 구현 완료]

구현: `Assets/Scripts/Proficiency`(`ProficiencySettings` 에셋 `Resources/Proficiency/ProficiencySettings.asset`, `ProficiencyRules`, `ProficiencyState`), `PlayerData.proficiencies`(`ProficiencyEntry`: 레시피 id, 누적 수치), `CraftingController.GrantResult`(보너스 적용·획득), `CraftResultPopup`(Game 씬). 아래 수치는 모두 설정 에셋 값이다.

- **대상: 레시피별.** 제작 시 매칭된 레시피가 숙련도의 대상이다. 같은 완성품을 만드는 레시피도 별개로 쌓인다. (완성품 16종에 레시피 49개)
- **효과: 품질 보너스.** 숙련도 레벨에 따라 총점(0~40)에 보너스를 더한다. 보너스는 **상한을 두어 숙련도만으로는 최상품(40)에 도달하지 못하게** 한다. 즉 숙련도로는 상품(30~39)까지만 올라가고, 최상품은 직접 만점 플레이가 필요하다. 최상품이 도전 과제로 남고 가격 구조(최상품 ×2)가 유지된다.
- **성장: 제작 총점만큼 쌓인다.** [확정] 획득량은 **보너스 적용 전 총점을 버림한 정수(0~40)**이다. **20점(중품) 미만이면 쌓이지 않는다.** 보너스 적용 전 총점이 정확히 **40점(최상품)이면 1.5배인 60점**을 얻는다. (39점 이하는 총점 그대로) 보너스 적용 후 점수를 기준으로 하면 숙련도가 높을수록 더 빨리 쌓이는 되먹임이 생기므로 쓰지 않는다.
- **단계와 레벨.** [확정] 단계는 **초급 → 중급 → 고급**이고 각 단계는 Lv1~9(총 27레벨)다. 고급 Lv9를 채우면 **Master**이며 더 쌓이지 않는다. 표기는 "초급 Lv.3", "Master" 같은 문구로 한다.
- **레벨별 필요 수치.** [확정] 레벨을 오를 때 필요한 수치다.
  - Common 초급 Lv1 = **100**. 같은 단계 안에서는 레벨마다 **×1.2**.
  - 단계가 넘어갈 때(Lv9 → 다음 단계 Lv1)는 **초급→중급 ×1.5, 중급→고급 ×1.5**.
  - 등급이 오를 때마다 **Lv1 시작 수치에 +50** (Uncommon 150, Rare 200, Unique 250, Legendary 300). 이후 배율은 같으므로 모든 값이 시작 수치에 비례한다. 등급은 **레시피 결과물의 등급**이다.
  - 수치는 반올림하지 않은 값으로 이어 계산하고, 레벨별 필요 수치는 **half-up 반올림한 정수**(`PriceRounding`과 같은 규칙)로 쓴다.
  - Common 값: 초급 100, 120, 144, 173, 207, 249, 299, 358, 430 / 중급 645, 774, 929, 1115, 1337, 1605, 1926, 2311, 2773 / 고급 4160, 4992, 5990, 7188, 8626, 10351, 12421, 14906, 17887. Master까지 합계 102,016.
- **이월.** [확정] 필요 수치를 넘긴 분량은 다음 레벨로 이월한다. 단계가 넘어갈 때도 같다. Master 총량을 넘는 분량은 버린다. 필요 수치(최소 100)가 한 번의 최대 획득량(60)보다 커서 한 번에 두 레벨 이상 오르지는 않는다.
- **보너스.** [확정] 레벨마다 **0.1점**씩 늘어(초급 Lv2 0.2 … 고급 Lv9(Lv27) 2.7) Master에서는 **총 3.0점**이다. **초급 Lv1은 보너스가 없다(0).** [확정, 2026-11-17] 다른 레벨 값은 그대로라 초급 Lv1 → Lv2에서 0 → 0.2로 오른다. 총점(0~40)에 더한다. **보너스 적용 전 총점이 40 미만일 때 보너스를 더해 39 이상이 되면 39로 맞춘다.** [확정] 최상품(40)은 **보너스 없이 직접 40점**을 얻어야만 나온다. (보너스 적용 전 총점이 40이면 보너스를 더하지 않는다.)
- **제작 횟수 참고** (총점 평균 30일 때, 전체 단계, 평균 20점이면 약 1.5배, 전부 최상품(획득 60)이면 약 0.5배): Common 약 3,400회, Uncommon 약 5,100회, Rare 약 6,800회, Unique 약 8,500회, Legendary 약 10,200회. 고급 단계 한 곳만 보면 Common 약 2,885회에서 Legendary 약 8,650회다.
- **제작 결과 팝업.** [확정] 지금(v1)은 제작 결과 팝업이 없다(완성품은 인벤토리에 들어가고 로그만 남는다). 이 단계에서 **결과 팝업을 새로 만들고 확인 버튼으로 닫는다.**
  - 표시 내용: **완성품 이름·등급·품질**, **숙련도 단계·레벨**, **이번 획득량**, **진행도(숫자 + 게이지, 예: 85 / 144)**, **품질 보너스 점수**(예: +0.3). 예: "철검 (Common) 상품 / 초급 Lv.3 (+32) / [게이지] 85 / 144 / 품질 보너스 +0.3"
  - 20점 미만이라 쌓이지 않았거나 이미 Master이면 **현재 단계·레벨만 표시**한다. (예: "초급 Lv.3", "Master")
  - 레벨업, 단계 상승, Master 도달은 **따로 강조하지 않는다.**
  - 표시하는 보너스는 현재 레벨의 보너스 값이다. 39 상한으로 실제 더해진 양이 줄어도 레벨 값 그대로 보여 준다. (제안)
  - **배치.** [확정] 완성품 **아이콘을 좌측 상단**에 두고 아이콘 위쪽을 아이템명 위쪽에 맞춘다. 아이템명은 **상단 중앙**이다. 긴 이름이 2줄이 되지 않도록 **이름과 등급·품질을 두 줄로 나눈다**(예: "철검" / "(Common) 상품"). 글자와 아이콘·버튼이 서로 겹치지 않고 팝업 밖으로 나가지 않게 한다. 아이콘은 글자와 겹치지 않는 한 최대한 오른쪽에 둔다.
  - 현재 수치(임시, 팝업 상자 위쪽 기준 px): 상자 700×390. 아이콘 100×100, 가로 90~190, 위 25. 이름 줄(글자 34) 위 25~75, 등급·품질 줄(글자 28) 위 80~120, 두 줄 모두 가로 200~500(폭 300). 숙련도 135~179, 진행도 게이지 190~230, 품질 보너스 240~280, 확인 버튼 아래 여백 20(225×75). 이름 폭 300은 현재 가장 긴 이름(사파이어 전투도끼, 284)에 맞춘 값이라 더 긴 이름을 추가하면 아이콘을 왼쪽으로 옮기고(최대 가로 10) 폭을 넓힌다.
- **튜토리얼.** [확정] 튜토리얼의 철검 제작도 숙련도에 쌓인다. 제작이 끝나면 **결과 팝업이 먼저 뜨고, 닫으면 튜토리얼 `Step_04` 팝업**이 뜬다. 튜토리얼 문구에 숙련도가 오른다는 내용을 추가한다(문구는 **[미정]**).
- **숙련도 확인 화면은 이 단계에서 만들지 않는다.** [확정] 숙련도 확인은 4번의 레시피 도감에서 한다. 이 단계에서는 숙련도 수치를 저장하고 결과 팝업의 표시만 둔다.
- 알 수 없는 제작품(§3)은 레시피가 없으므로 숙련도가 없다.
- 아래는 **[미정]**: 결과 팝업의 디자인(스프라이트·색·글꼴, 위 배치 원칙 밖의 세부 수치), 숙련도 안내 튜토리얼 문구.

### 구조 메모
- 정적 데이터와 런타임 상태 분리: 숙련도는 `PlayerData` 쪽 런타임 상태로 두고(레시피 id → **누적 숙련도 정수 한 개**), 레벨은 필요 수치표의 누적 합으로 계산한다. 이월이 따로 필요 없다. 시작 수치·배율·보너스 값은 ScriptableObject 데이터로 둔다.
- 보너스 적용 위치는 `CraftScoring`의 총점 계산이다. 적용 후 품질 구간 경계(버림)는 그대로 쓴다.
- 결과 팝업은 `BlackSmith.UI`에 두고 `CraftingController.CraftFinished`를 듣고 표시한다. 확인 버튼은 `ButtonLabelPress`를 붙인다. 튜토리얼은 결과 팝업이 닫힌 뒤에 `Step_04`로 넘어가야 하므로 `TutorialFlow`/`TutorialController`에 대기 조건이 필요하다.
- 세이브: `SaveFile`에 숙련도를 추가한다. 필드가 없는 옛 세이브는 빈 값으로 읽는다. (도감 해금 목록은 4번에서 추가한다.)

## 3. 레시피 습득 [확정된 결정 / 세부 미정]

4번 단계에서 한 번에 도입한다. 지금(v1) 구현은 "가장 가까운 레시피를 자동 선택하고 레시피 북은 비공개"이며, 이 단계에서 아래로 바뀐다.

**레시피 도감**
- 레시피 도감을 추가한다. 제작을 통해 아이템을 만들면 해당 레시피가 도감에서 해금되어 플레이어가 확인할 수 있다.
- 한 번 이상 제작해 해금한 레시피만 목록에 올라간다. 항목은 **완성품 이름 + 정식 레시피의 재료 구성 + 숙련도 레벨**이다.
- **해금 시점: 제작 완료 시.** 품질이 최하품이어도 해금되고 숙련도는 0으로 시작한다.
- **각 장비의 숙련도도 도감에서 확인한다.**
- 도감은 상점이나 저장 패널처럼 UI 패널로 확인한다. **여는 방법은 저장 버튼 옆에 버튼을 추가해 패널을 여는 것으로 계획한다.** (패널 모양, 정렬, 표시 정보는 **[미정]**)

**정확 일치 매칭**
- v1의 "가까운 레시피" 점수제는 폐지하고 **정확히 일치해야만** 레시피가 선택된다.
- 일치 기준은 **재료 종류 + 수량**이다. 같은 이름의 다른 등급 아이템은 없으므로 등급은 일치 여부와 무관하다.
- 투입한 재료는 지금과 같이 제작을 시작할 때 모두 소모된다. (제안)
- 이 단계에서 `GameDesign.md`의 레시피 매칭 규칙과 콘텐츠 제작 규칙("일치하는 레시피가 없는 경우는 없어야 한다")을 교체한다. 튜토리얼 문구(`Step_04`의 "가장 가까운 제작법")도 같이 고친다.

**알 수 없는 제작품**
- 레시피가 없는 조합으로 제작하면 **"알 수 없는 제작품"**이 나온다.
- Common 등급 완성품이며 **ID는 `999`**, 아이콘은 **[미정]**이다.
- 판매가는 **품질과 관계없이 50골드 고정**이다. (가장 싼 재료도 100골드이므로 정확히 일치하지 않는 제작은 항상 손해다. 제안)
- 도감에 해금되지 않고 숙련도도 없다. 미니게임 **난이도는 2로 고정**한다.
- 품질은 지금처럼 미니게임 점수로 정해지지만 가격과 숙련도에는 영향이 없다. (제안)

**[미정]**
- 도감 UI 세부, 도감을 채우는 다른 경로 유무(상점, 보상 등), 해금 시 알림 여부, 알 수 없는 제작품의 아이콘.

### 구조 메모
- 이 기능은 `GameDesign.md`·`CoreLoop.md`·`CLAUDE.md`의 "레시피 북은 플레이어에게 보이지 않는다"와 충돌하므로, 구현 시 해당 문서를 "해금한 레시피만 도감에 표시"와 정확 일치 매칭으로 갱신한다.
- 알 수 없는 제작품은 `CraftedItemData` 한 개이고, 가격과 난이도는 레시피가 없는 경우의 별도 분기가 필요하다.
- 세이브: 도감 해금 목록을 `SaveFile`에 추가한다. 필드가 없는 옛 세이브는 빈 값으로 읽는다.

## 4. 적중 이펙트 [확정된 결정, 구현 완료]

설계: [superpowers/specs/2026-11-17-hit-effects-design.md](superpowers/specs/2026-11-17-hit-effects-design.md). 리듬게임식 손맛을 판정 순간의 시각 연출로 보강한다.

- **대상: 단조와 연마.** [확정] 가열·열처리는 넣지 않는다.
- **단조:** [확정] 원이 판정될 때 그 원 자리에서 **금색 계열 빛**이 난다. 크기는 **Perfect > Good > 눌렀지만 Miss**. **누르지 못하고 놓친 Miss는 빛이 없다.** 원이 없는 빈 곳 클릭도 없다. 판정 정보는 기존 원 색(녹/노/빨)이 맡는다.
  - **모양: 도넛형.** [확정, 2026-11-17] 빛은 **원 바깥으로만** 퍼지고 **원은 가리지 않는다.** 링의 구멍이 판정 원(안쪽 원) 가장자리에서 시작해 바깥으로만 커지고, 불꽃도 원 가장자리 바깥에서 생긴다. 판정별 차이는 퍼지는 정도·불꽃 수·밝기로 낸다.
- **연마:** [확정] 흠집 하나를 다 지울 때마다 그 자리에서 **은색 계열 반짝임**. 모든 흠집에 같은 크기이며 **흠집 크기 정도**다(도넛 아님, 2026-11-17).
- **방식: 파티클.** [확정] 파티클이 UI 위에 보이도록 Game 씬 `GameUICanvas`를 Screen Space - Camera로 바꿨다. 이펙트는 프리팹(`Assets/Effects/ForgeHitPerfect/Good/Miss.prefab`, `PolishSparkle.prefab`)만 바꿔 교체한다. 크기는 실제 원·흠집 지름에 맞춰 자동으로 키우거나 줄인다(기준 지름 단조 160px, 연마 180px).
- 현재 값(임시): 금색 (1, 0.82, 0.35), 은색 (0.85, 0.88, 0.95). 단조 링 바깥 지름 Perfect 512 / Good 432 / 눌렀지만 Miss 368px(원 160px 기준), 불꽃 16 / 10 / 5개. 연마 빛 지름 = 흠집 지름(×0.9→1.15). 재생 0.5초 안팎.
- **[미정]**: 이펙트 최종 아트(텍스처·모양·색).

## 6. 리스크

- 숙련도 보너스와 레시피 습득이 둘 다 진행 속도와 수익에 영향을 줄 수 있으므로, 수익이 과도해지지 않게 마지막 밸런스 단계에서 함께 본다.
- 정확 일치로 실수한 제작의 손실이 커진다(재료 소모, 판매가 50). 튜토리얼과 도감이 이를 충분히 알려 주는지 직접 플레이로 확인한다.
- 세이브 호환: 새 필드는 모두 "없으면 기본값"으로 읽는다.
