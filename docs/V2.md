## 2. 숙련도 [확정된 결정]

- **대상: 레시피별.** 제작 시 매칭된 레시피가 숙련도의 대상이다. 같은 완성품을 만드는 레시피도 별개로 쌓인다. (완성품 16종에 레시피 49개)
- **효과: 품질 보너스.** 숙련도 레벨에 따라 총점(0~40)에 보너스를 더한다. 보너스는 **상한을 두어 숙련도만으로는 최상품(40)에 도달하지 못하게** 한다. 즉 숙련도로는 상품(30~39)까지만 올라가고, 최상품은 직접 만점 플레이가 필요하다. 최상품이 도전 과제로 남고 가격 구조(최상품 ×2)가 유지된다.
- **성장: 품질에 따라 쌓인다.** **중품(20점) 미만이면 쌓이지 않고, 중품 이상일 때만 쌓인다.** 품질이 높을수록 더 쌓일지, 중품 이상은 동일하게 쌓일지는 **[미정]**.
- **변화 표시.** 제작이 끝날 때 결과 팝업에 숙련도 변화를 간단히 표시한다. (예: 철검 숙련도 Lv.3 (+1))
- **숙련도 확인 화면은 이 단계에서 만들지 않는다.** [확정] 숙련도 확인은 4번의 레시피 도감에서 한다. 이 단계에서는 숙련도 수치를 저장하고 결과 팝업의 변화 표시만 둔다.
- 알 수 없는 제작품(§3)은 레시피가 없으므로 숙련도가 없다.
- 아래는 **[미정]**: 레벨 수, 레벨별 필요 수치, 보너스 크기와 상한 값, 품질별 가중치.

### 구조 메모
- 정적 데이터와 런타임 상태 분리: 숙련도는 `PlayerData` 쪽 런타임 상태로 두고(레시피 id → 수치), 레벨별 수치·보너스는 ScriptableObject 데이터로 둔다.
- 보너스 적용 위치는 `CraftScoring`의 총점 계산이다. 적용 후 품질 구간 경계(버림)는 그대로 쓴다.
- 세이브: `SaveFile`에 숙련도를 추가한다. 필드가 없는 옛 세이브는 빈 값으로 읽는다. (도감 해금 목록은 4번에서 추가한다.)

## 3. 레시피 습득 [확정된 결정 / 세부 미정]

4번 단계에서 한 번에 도입한다. 지금(v1) 구현은 "가장 가까운 레시피를 자동 선택하고 레시피 북은 비공개"이며, 이 단계에서 아래로 바뀐다.

**레시피 도감**
- 레시피 도감을 추가한다. 제작을 통해 아이템을 만들면 해당 레시피가 도감에서 해금되어 플레이어가 확인할 수 있다.
- 한 번 이상 제작해 해금한 레시피만 목록에 올라간다. 항목은 **완성품 이름 + 정식 레시피의 재료 구성 + 숙련도 레벨**이다.
- **해금 시점: 제작 완료 시.** 품질이 최하품이어도 해금되고 숙련도는 0으로 시작한다.
- **각 장비의 숙련도도 도감에서 확인한다.**
- 도감은 상점이나 저장 패널처럼 UI 패널로 확인한다. **여는 방법은 저장 버튼 옆에 버튼을 추가해 패널을 여는 것으로 계획한다.** (패널 모양, 정렬, 표시 정보는 **[미정]**)

**정확 일치 매칭**
- v1의 "가까운 레시피" 점수제는 폐지하고 **정확히 일치해야만** 레시피가 선택된다.
- 일치 기준은 **재료 종류 + 수량**이다. 같은 이름의 다른 등급 아이템은 없으므로 등급은 일치 여부와 무관하다.
- 투입한 재료는 지금과 같이 제작을 시작할 때 모두 소모된다. (제안)
- 이 단계에서 `GameDesign.md`의 레시피 매칭 규칙과 콘텐츠 제작 규칙("일치하는 레시피가 없는 경우는 없어야 한다")을 교체한다. 튜토리얼 문구(`Step_04`의 "가장 가까운 제작법")도 같이 고친다.

**알 수 없는 제작품**
- 레시피가 없는 조합으로 제작하면 **"알 수 없는 제작품"**이 나온다.
- Common 등급 완성품이며 **ID는 `999`**, 아이콘은 **[미정]**이다.
- 판매가는 **품질과 관계없이 50골드 고정**이다. (가장 싼 재료도 100골드이므로 정확히 일치하지 않는 제작은 항상 손해다. 제안)
- 도감에 해금되지 않고 숙련도도 없다. 미니게임 **난이도는 2로 고정**한다.
- 품질은 지금처럼 미니게임 점수로 정해지지만 가격과 숙련도에는 영향이 없다. (제안)

**[미정]**
- 도감 UI 세부, 도감을 채우는 다른 경로 유무(상점, 보상 등), 해금 시 알림 여부, 알 수 없는 제작품의 아이콘.

### 구조 메모
- 이 기능은 `GameDesign.md`·`CoreLoop.md`·`CLAUDE.md`의 "레시피 북은 플레이어에게 보이지 않는다"와 충돌하므로, 구현 시 해당 문서를 "해금한 레시피만 도감에 표시"와 정확 일치 매칭으로 갱신한다.
- 알 수 없는 제작품은 `CraftedItemData` 한 개이고, 가격과 난이도는 레시피가 없는 경우의 별도 분기가 필요하다.
- 세이브: 도감 해금 목록을 `SaveFile`에 추가한다. 필드가 없는 옛 세이브는 빈 값으로 읽는다.

## 5. 리스크

- 숙련도 보너스와 레시피 습득이 둘 다 진행 속도와 수익에 영향을 줄 수 있으므로, 수익이 과도해지지 않게 마지막 밸런스 단계에서 함께 본다.
- 정확 일치로 실수한 제작의 손실이 커진다(재료 소모, 판매가 50). 튜토리얼과 도감이 이를 충분히 알려 주는지 직접 플레이로 확인한다.
- 세이브 호환: 새 필드는 모두 "없으면 기본값"으로 읽는다.
