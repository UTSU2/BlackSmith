# GameDesign — 게임 전체 기획

> 표기 규칙: **[확정]** 논의로 정해진 내용 / **[미정]** 아직 정해지지 않았으며 임의로 결정하지 않는다.

## 1. 개요 [확정]

- 제목: BlackSmith
- 장르: 2D 대장장이 제작 게임
- 엔진/언어: Unity 6 (`6000.3.27f2`), C#
- 개발 형태: 1인 개발
- 핵심 시스템
  - 재료를 사용한 장비 제작
  - 장비 등급 결정
  - 등급에 따른 판매 가격 결정
  - 판매 수익으로 새로운 고등급 장비 제작

## 2. 컨셉 [확정]

- 현실의 제작과 달리 **빠른 리듬게임처럼 속도감 있게** 진행한다.
- 제작은 4개의 미니게임(가열 → 단조 → 열처리 → 연마)으로 구성된다.
- 입력은 마우스(클릭, 누름/뗌, 드래그)를 사용한다.
  - 마우스 외 입력(컨트롤러, 터치 등) 지원 여부: **[미정]**

## 3. 시스템 목록

| 시스템 | 내용 | 상태 |
|---|---|---|
| 아이템 데이터 | 광물(구매/판매), 제작품(판매 전용), 등급별 판매가 배율 구조 | 구현됨 (등급 이름/개수/배율 값은 임시) |
| 상점 | 광물 구매, 장비 판매 | 기획 확정(기능), UI/세부 [미정], 미구현 |
| 제작 | 가열 → 단조 → 열처리 → 연마 (4개 미니게임) | 조작 방식 확정, 난이도 1~10단계 확정(수치 [미정]), 판정 세부 [미정], 미구현 |
| 등급 | 제작 완성도에 따라 결정 | 완성도 계산, 등급 이름/개수 [미정] |
| 판매가 | 기본 판매가 × 등급 배율 | 구조만 있음, 값 [미정] |
| 재화/인벤토리/저장 | 돈, 보유 아이템, 저장/불러오기 | 세부 [미정], 미구현 |

## 4. 제작 미니게임 [조작 방식 확정]

| 순서 | 단계 | 조작 방식 | 완성도 판정 |
|---|---|---|---|
| 1 | 가열 | 마우스를 누르다 떼기를 반복해 바(bar)를 일정한 위치에 유지 | [미정] |
| 2 | 단조 | 화면 여러 곳에 원이 생성되어 줄어들고, 안쪽에 그려진 원과 맞는 타이밍에 클릭 (리듬게임 형식) | [미정] |
| 3 | 열처리 | 게이지 바 안에서 작은 오브젝트가 좌우로 왕복하며, 특정 위치에 도달할 때 클릭 | [미정] |
| 4 | 연마 | 사포질하듯 흠집 부분을 클릭한 뒤 슬라이드(드래그)하여 갈아냄 | [미정] |

각 단계의 완성도가 장비 등급에 반영된다.

### 난이도 [일부 확정]

- 제작 미니게임의 난이도는 **1단계부터 10단계까지**다. [확정]
- 제작에 사용되는 **재료 아이템의 등급**에 따라 미니게임 난이도가 바뀐다. [확정]
- 재료 아이템의 등급마다 **점수**를 부여한다. [확정] (점수 값은 [미정])
- 사용한 재료의 점수를 **개수만큼 합산한 뒤 개수로 나눈 값(평균)**을 난이도 점수로 쓴다. 같은 재료를 많이 넣어도 평균이므로 양은 난이도에 영향을 주지 않고, 등급이 다른 재료를 섞어도 같은 방식으로 계산한다. [확정]
- 난이도 점수가 **일정 점수 이상이 될 때마다 난이도가 1단계씩 올라간다**. [확정] (기준 점수는 [미정])
- 아래는 모두 **[미정]**
  - 등급별 점수 값
  - 난이도가 오르는 "일정 점수"의 기준값과 방식(같은 간격마다인지, 단계마다 다른지), 평균의 소수 처리, 기준 미만일 때의 시작 단계
  - 난이도가 높아질수록 어떻게 바뀌는지(속도, 크기, 개수 등)와 단계별 수치
  - 4개 미니게임에 같은 난이도가 적용되는지, 단계별로 따로 정해지는지
  - 난이도가 결과 등급에 직접 영향을 주는지
  - 난이도 단계를 플레이어에게 표시하는지

**[미정]** 항목
- 단계별 판정 기준, 점수식, 실패 처리
- 난이도 단계(1~10)별 변수 수치(속도, 크기, 개수 등)와 등급별 점수 값, 난이도가 오르는 기준 점수
- 완성도 값의 범위, 단계별 가중치, 등급 산식
- 1회 제작의 목표 소요 시간
- 난이도가 등급에 직접 영향을 주는지

## 5. 등급과 가격

- 장비 등급은 제작 완성도로 결정된다. [확정]
- 판매 가격은 등급에 따라 달라진다. [확정]
- 현재 코드 구조: 판매가 = 기본 판매가 × 등급별 배율 (값은 임시). [구현됨]
- 등급 이름, 개수, 배율 값, 완성도→등급 변환 방식: **[미정]**

## 6. 후속 기능 (핵심 시스템 완성 후 추가) [확정: 추가 예정 / 세부 미정]

| 기능 | 내용 | 미정 사항 |
|---|---|---|
| 장비 강화 | 장비 강화 수치 도입. 판매가는 등급과 강화 수치 모두에 따라 결정 | 강화 방식, 실패 여부, 비용, 가격 공식 |
| 숙련도 시스템 | 제작 숙련도 도입 | 숙련도의 대상(플레이어/장비 종류), 성장 방식, 효과 |
| 레시피 해금 | 메인 루프에는 포함하지 않음. 도입 여부 자체가 미정 | 도입 여부, 방식 |
