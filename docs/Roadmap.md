# Roadmap — 개발 단계별 계획

> **상태: 확정.** 단, 각 단계의 기간과 일정은 **[미정]**이다.

## 1. 의존 관계

- 상점은 인벤토리와 재화에 의존한다.
- 제작은 재료 소모와 결과 장비 생성(인벤토리)에 의존한다.
- 품질 판정은 제작 미니게임 점수에 의존한다. 완성품 등급은 레시피에 정의된다.
- 판매가는 레시피의 재료 구매가와 품질에 의존한다.
- 제작 시작 시 투입 재료로 레시피를 찾는 매칭이 필요하다. (레시피 북은 플레이어에게 보이지 않음)
- 강화, 숙련도는 제작 시스템과 저장 데이터에 의존한다. 강화는 개별 장비가 등급·품질·강화 수치를 상태로 가져야 한다.

## 2. 단계

| 단계 | 내용 | 기간 |
|---|---|---|
| 0. 기반 (진행 중) | 타이틀/Game 씬 배경, 아이템 데이터 레이어 | - |
| 1. 기반 시스템 | 재화, 인벤토리, 저장/불러오기 (장비가 등급·품질 등 개별 상태를 가질 수 있는 구조 고려) | [미정] |
| 2. 상점 | 광물 구매, 장비 판매 UI와 기능 | [미정] |
| 3. 제작 미니게임 | 단조 우선 → 가열, 열처리, 연마 | [미정] |
| 4. 품질/판매가 | 미니게임 점수 → 품질, 재료 구매가 합 × 품질 배율 → 판매가 연결, 레시피 매칭 | [미정] |
| 5. 밸런스 | 재료 가격, 판매가, 제작 시간 조정 | [미정] |
| 6. 후속 기능 | 숙련도, 강화 (레시피 해금은 도입 여부 [미정]) | [미정] |

- 품질 산식은 확정이다. (단계당 10점, 합계 40점, 5구간, 경계는 버림)
- 단계 3 전에 미니게임 세부 규칙(판정, 난이도 단계별 수치, 제작 시간)을 먼저 정한다. 해당 규칙은 현재 **[미정]**이다.
  - 난이도는 1~10단계이고 기본값은 레시피에 정의하며, 레시피 등급보다 높은 재료를 쓰면 가중이 붙는 구조까지는 확정이다. 단계별 수치는 **[미정]**이다.
- 콘텐츠 제작 시 규칙: 모든 등급의 각 광물마다 이를 쓰는 레시피가 최소 하나 있어야 하고, 아이템을 추가하면 그 아이템을 쓰는 레시피도 함께 만든다.
- 재료·완성품·레시피 콘텐츠는 후반에 한꺼번에 작성한다. 각 아이템의 Common 가격은 아이템 생성 시 정한다.

## 3. 1인 개발 리스크

- 미니게임 4개는 범위가 크다. 하나씩 완성해 검증한다.
- 리듬게임식 손맛은 판정 정밀도, 입력 지연 대응, 적중 사운드와 이펙트에 크게 의존한다.
- 사양이 미정인 상태에서 UI와 저장을 먼저 만들면 재작업이 생긴다.
- 밸런스 조정은 반복 작업이므로 수치를 데이터로 분리해 둔다. 난이도 10단계 x 미니게임 4개의 수치도 같은 방침으로 데이터(ScriptableObject)에 둔다.
- 에셋 스타일 불일치와 라이선스는 배포 전 확인이 필요하다.
- 같은 제작 과정의 반복에 따른 피로 완화 방법: **[미정]**
- 데이터 구조 변경 시 세이브 호환성 문제가 생길 수 있다.
