# Roadmap — 개발 단계별 계획

> **상태: 확정.** 단, 각 단계의 기간과 일정은 **[미정]**이다.

## 1. 의존 관계

- 상점은 인벤토리와 재화에 의존한다.
- 제작은 재료 소모와 결과 장비 생성(인벤토리)에 의존한다.
- 등급 판정은 제작 완성도에 의존한다.
- 판매가는 등급에 의존한다.
- 강화, 숙련도는 제작 시스템과 저장 데이터에 의존한다. 강화는 개별 장비가 등급·강화 수치를 상태로 가져야 한다.

## 2. 단계

| 단계 | 내용 | 기간 |
|---|---|---|
| 0. 기반 (진행 중) | 타이틀/Game 씬 배경, 아이템 데이터 레이어 | - |
| 1. 기반 시스템 | 재화, 인벤토리, 저장/불러오기 (장비가 등급 등 개별 상태를 가질 수 있는 구조 고려) | [미정] |
| 2. 상점 | 광물 구매, 장비 판매 UI와 기능 | [미정] |
| 3. 제작 미니게임 | 단조 우선 → 가열, 열처리, 연마 | [미정] |
| 4. 등급/판매가 | 완성도 → 등급 → 판매가 연결 | [미정] |
| 5. 밸런스 | 재료 가격, 판매가, 제작 시간 조정 | [미정] |
| 6. 후속 기능 | 숙련도, 강화 (레시피 해금은 도입 여부 [미정]) | [미정] |

- 단계 3과 4 사이에서 등급 산식이 정해져야 한다. 등급 산식은 현재 **[미정]**이다.
- 단계 3 전에 미니게임 세부 규칙(판정, 난이도, 제작 시간)을 먼저 정한다. 해당 규칙은 현재 **[미정]**이다.
  - 난이도는 1~10단계이고 재료 등급별 점수의 평균이 기준을 넘을 때마다 오르는 구조까지는 확정이다. 등급별 점수 값, 기준 점수, 단계별 수치는 **[미정]**이다.

## 3. 1인 개발 리스크

- 미니게임 4개는 범위가 크다. 하나씩 완성해 검증한다.
- 리듬게임식 손맛은 판정 정밀도, 입력 지연 대응, 적중 사운드와 이펙트에 크게 의존한다.
- 사양이 미정인 상태에서 UI와 저장을 먼저 만들면 재작업이 생긴다.
- 밸런스 조정은 반복 작업이므로 수치를 데이터로 분리해 둔다. 난이도 10단계 x 미니게임 4개의 수치도 같은 방침으로 데이터(ScriptableObject)에 둔다.
- 에셋 스타일 불일치와 라이선스는 배포 전 확인이 필요하다.
- 같은 제작 과정의 반복에 따른 피로 완화 방법: **[미정]**
- 데이터 구조 변경 시 세이브 호환성 문제가 생길 수 있다.
