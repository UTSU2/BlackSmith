# Tutorial — 튜토리얼 설계

> **상태: 확정, 구현 완료** (미정: 팝업 문구, 미니게임 조작 안내 여부, 팝업 디자인은 임시값). v2 범위. 아래 **[미정]** 항목은 임의로 정하지 않는다.

## 1. 목적

- 새 게임 플레이어가 첫 장비를 직접 만들어 팔아 보면서 **재료 투입과 매칭 규칙**을 익힌다.
- 해금 전에는 레시피가 보이지 않고 투입한 재료가 제작 시작 시 모두 소모되므로, 가르치지 않으면 재료를 낭비하기 쉽다. (v2부터 정확히 일치하지 않으면 알 수 없는 제작품이 된다)

## 2. 목표 / 비목표

- 목표: 구매 → 제작 → 판매 한 바퀴를 끝까지 체험시키고, 설명 팝업으로 규칙을 알려 준다.
- 비목표: 4개 미니게임 조작법 상세 교육, 등급·품질·가격 공식 설명, 레시피 해금. (미니게임 조작 안내 팝업을 넣을지는 **[미정]**)
- 안티 목표: 재료 낭비로 흐름이 끊기는 것, 튜토리얼 로직이 상점·저장 UI 곳곳에 흩어지는 것.

## 3. 흐름 (확정된 결정)

1. 새 게임 시작 시 **재료 구매용 금액만** 지급한다. 금액 = 튜토리얼 정답 재료의 구매가 합(값을 새로 정하지 않고 계산으로 구한다).
2. 상점에서는 **튜토리얼 재료만 구매 가능**하다. 나머지 광물은 잠긴다.
3. 첫 제작: 팝업이 **정답 재료와 수량을 그대로 알려 준다.**
4. 제작 완료 후: 팝업이 **매칭 규칙을 설명**한다. (v1 설계: 수량만 본다 / 가장 가까운 레시피로 만들어진다 / 투입한 재료는 모두 소모된다. v2부터 매칭은 정확 일치이므로 문구를 바꿔야 한다 — 아래 "정확 일치 도입 시 주의")
5. 완성품을 상점에서 판매하면 튜토리얼이 끝나고 **1000원을 지급**한다. (`CompleteTutorial()`)
6. **스킵은 없다.** 새 게임에서는 반드시 거친다.
7. 튜토리얼 중에는 **저장을 막는다.** 도중에 타이틀로 나가면 진행은 사라지고 새 게임은 처음부터 다시 시작한다. 단계 진행도는 세이브에 저장하지 않는다.
8. 옛 세이브(`tutorialPending` 필드 없음)는 지금처럼 완료로 처리하며 보상이 없다.

## 4. 접근 방식

| 안 | 내용 | 평가 |
|---|---|---|
| **A. 단계 데이터 + 컨트롤러 (채택)** | 단계를 ScriptableObject로 두고 `TutorialController`가 기존 이벤트로 진행. 상점·저장 UI는 "튜토리얼 중인가 / 이 품목이 허용되는가"만 질의 | 문구·순서를 데이터로 수정, 제한을 한곳에서 관리. 초기 구조 비용 |
| B. 코루틴 하드코딩 | 한 스크립트에 순서를 직접 작성 | 빠르지만 문구 수정이 코드 수정, 분기가 흩어짐 |
| C. 전용 씬 | 제한된 상점·제작 UI를 복제 | UI가 두 벌이 되어 유지 부담 |

## 5. 구조 (A안)

- `TutorialStepData` (ScriptableObject): 팝업 문구, 완료 조건 종류, 허용 구매 품목. 단계 순서는 목록(에셋)으로 둔다.
- `TutorialController` (`BlackSmith.Tutorial` 등 새 폴더/네임스페이스는 폴더와 맞춘다): 현재 단계 보유, 이벤트를 듣고 다음 단계로 이동. 구독은 `OnDisable`에서 해제한다.
- 이벤트 소스: 제작은 `CraftingController.CraftStarted/CraftFinished`가 이미 있다. **상점 구매/판매 완료 이벤트는 확인 후 없으면 추가**한다.
- 게이트 질의: 상점은 품목별 구매 허용 여부, 저장 패널은 저장 가능 여부, 설정 패널은 타이틀 복귀 확인창 표시 여부를 컨트롤러에 묻는다.
- 팝업 UI는 `BlackSmith.UI`에 두고, 글자가 있는 버튼은 `ButtonLabelPress`를 붙인다.
- `GameSession.StartNew`: 시작 지급을 추가하고 `CompleteTutorial()`은 튜토리얼 마지막 단계로 옮긴다. `StartTutorial()`은 유지한다.

## 6. 미정 / 빌더 몫

- 튜토리얼 장비·레시피: **철검(`iron_sword`)** — **[확정]** (§7 참고)
- 팝업 문구 전부 — **[미정]**
- 미니게임 조작 안내 팝업 여부 — **[미정]**
- 팝업 디자인(위치, 화면을 가리는지, 해당 UI 강조 여부) — **[미정]**
- 잠긴 책 버튼의 피드백(튜토리얼 중 책 버튼이 눌려도 아무 일도 없음) — **[미정]**
- 팝업 자리표시자 배치: 1000x220, 임시. 위치는 단계 에셋(`TutorialStepData.popupPosition`)이 정한다. 상점 안에서 진행하는 단계 1(구매)·5(판매)는 화면 하단 중앙(위쪽 탭 버튼을 가리지 않게), 나머지와 완료 안내는 상단 중앙. 상단은 패널 제목 영역을, 하단은 상점 목록 아래쪽 약 80px을 가리며 최종 배치는 **[미정]**.
- 시작 지급 금액은 정답 재료 구매가 합으로 계산한다. 등급별 가격 배율(`ItemGradeInfo`)과 반올림 규칙을 그대로 따른다.
- 제작 도중 비정상 종료·씬 전환 시 컨트롤러 상태 정리 방식은 구현 시 정한다.

### 구현 현황과 설계 대비 달라진 점

구현됨: `TutorialConfig`/`TutorialStepData`/`TutorialCondition`과 에셋(`Assets/Resources/Tutorial/`, 6단계), `TutorialFlow`(순수 C#), `TutorialController`, `TutorialPopup`, 상점 필터, 책 버튼 잠금, 설정 패널 타이틀 복귀 확인창.

- 팝업 문구는 모두 `[임시]` 자리표시자다. `Assets/Resources/Tutorial/Step_*.asset`, `TutorialConfig.asset`, `SettingsPanel.tutorialConfirmMessage`에 있으며 최종 문구는 **[미정]**이다.
- 저장 막기는 책 버튼(저장·불러오기 탭 모두)을 튜토리얼 중 완전히 잠그는 방식으로 구현했다.
- 보상은 철검을 판매한 직후 지급하고, 완료 안내 팝업은 그 뒤에 뜬다. 철검 판매금은 회수하고 소지금을 정확히 1000원으로 맞춘다(`CompleteTutorial`).
- 설계에 없던 항목: 판매 목록도 철검만 보이게 필터링한다(철 원석을 되팔아 흐름이 깨지는 것을 막기 위함). 구매 목록은 철 원석만 보인다.

## 7. 튜토리얼 콘텐츠 [확정: 철 원석 → 철검]

현재 에셋 기준 값이다. 시작 지급 금액은 아래 값을 계산해서 구하므로 가격이 바뀌어도 맞춰 따라간다.

| 항목 | 값 |
|---|---|
| 레시피 | `iron_sword` (결과: 철검, `baseDifficulty` 1) |
| 정답 재료 | 철 원석(id `1`, Common) × 1 |
| 철 원석 구매가 | 100원 (Common 기준, 등급 배율 ×1) |
| 시작 지급 | 100원 (= 정답 재료 구매가 합) |
| 구매 가능 품목 | 철 원석만 |
| 철검 판매가 | 재료 구매가 100 × 품질 배율(0.7 / 1 / 1.2 / 1.5 / 2) = 70 ~ 200원 |
| 완료 보상 | 1000원 (`TutorialRewardMoney`) |

- 시작 지급이 정확히 철 원석 1개 값이라 다른 수량을 살 수 없다. 수량 제한 코드는 필요 없다.
- 정답 재료가 1종 1개라 매칭 규칙 설명(§3-4)에서 수량이 중요하다는 점을 보여 주기 좋다. 같은 철 원석을 2개 넣으면 철검이 아니라 다른 레시피(철 도끼, `recipe_iron_axe`: 철 원석 × 2)가 만들어진다. 이 예시를 팝업 문구에 쓸지는 **[미정]**.
- 철 원석 외 다른 재료를 같이 넣으면 철 곡괭이·철퇴 등 다른 레시피와 매칭될 수 있다. 첫 제작 팝업이 정답을 알려 주므로 튜토리얼 중 투입 UI에서 다른 재료를 쓸 수 없는 것은 구매 제한으로 이미 보장된다.

## 8. 검증

- 튜토리얼 중: 허용되지 않은 광물은 구매할 수 없고, 저장 버튼이 잠기며, 타이틀 복귀 시 확인창이 뜬다.
- 완료 후: 1000원 지급, 저장·구매 제한 해제, 이후 세이브에 `tutorialPending`이 완료로 기록된다.
- 옛 세이브 로드 시 튜토리얼이 뜨지 않는다.

### 검증 현황

- 확인함 (에디터 플레이 모드에서 메서드·이벤트를 직접 호출): 전체 흐름(구매 목록 이름, 돈 100 → 0 → 1150(회수 변경 전. 변경 후는 판매 뒤 항상 1000, 에디터에서 `PlayerData`로 확인), 완료 팝업, 불러온 게임 상태). Game/Title 씬 Missing Script 0.
- 어디에서도 확인하지 못함: `MainMenu.OnNewGame` 이후의 실제 `Start()` 경로, 팝업 모양/위치, 실제 마우스 클릭, 실제 제작 UI 이벤트, 튜토리얼이 아닐 때의 타이틀 복귀 경로.
- 빌드에서 직접 플레이로 확인 필요: Title → 새 게임 → 확인 → 구매 → 제작 → 확인 → 판매 → 확인 → 저장 → 타이틀 → 불러오기, 그리고 설정 → 타이틀 (튜토리얼 중 / 완료 후 저장하지 않은 변경이 있을 때).

### 숙련도 도입 시 주의

- v2 2번에서 제작 결과 팝업이 생겼다(구현됨). 튜토리얼 제작이 끝나면 결과 팝업과 숙련도 안내가 함께 뜨고, 결과 팝업이 닫힌 뒤에 `Step_04` 팝업으로 넘어간다(아래 숙련도 안내 단계). 철검 제작도 숙련도에 쌓이며, 튜토리얼 문구에 숙련도가 오른다는 내용을 추가한다(문구 **[미정]**). ([V2.md](V2.md) §2)
- **숙련도 안내 단계 [확정, 2026-11-17, 구현됨]:** 제작이 끝나면 결과(숙련도) 팝업과 **동시에** 숙련도 안내 문구가 **상단** 튜토리얼 팝업으로 나온다(확인 버튼·배경 막기 없음). 결과 팝업의 확인을 누르면 `Step_04`(제작법 설명)로 넘어간다. 순서는 `Step_03`(제작 완료, 제작이 끝나면 바로 완료) → `Step_03_Proficiency`(조건 `CraftResultClosed` = 결과 팝업이 닫힐 때 완료) → `Step_04`. 튜토리얼 팝업 캔버스 순서는 21로 결과 팝업(20)보다 위다. 안내 문구는 `[임시]`이며 내용은 **[미정]**(사용자가 에셋에서 직접 고친다). `TutorialController.resultPopup`이 비어 있으면 안내 단계는 제작 완료 직후 바로 넘어간다.

### 정확 일치 도입 시 주의

- **v2 4번에서 레시피 매칭이 정확 일치로 바뀌었다 (구현됨).** `Step_04`의 "가장 가까운 제작법에 따라…" 설명은 이제 틀리므로 문구를 고쳐야 한다(사용자가 에셋에서 직접 고친다, 문구 **[미정]**). 철 원석 ×1 → 철검은 정확 일치라 흐름은 그대로 동작하고, 첫 제작으로 철검이 도감에 해금되어 결과 팝업에 "새 레시피 해금! (No.1)" 줄이 같이 보인다. 튜토리얼 중에도 도감 버튼은 열린다. ([V2.md](V2.md) §3)
