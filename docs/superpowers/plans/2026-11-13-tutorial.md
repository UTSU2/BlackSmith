# 튜토리얼 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 새 게임에서 철 원석 구매 → 철검 제작 → 판매를 안내하는 필수 튜토리얼(스킵 없음)을 넣는다.

**Architecture:** 단계(문구, 완료 조건)를 ScriptableObject로 두고, 순수 C# `TutorialFlow`가 이벤트를 받아 단계를 넘긴다. `TutorialController`(MonoBehaviour)가 기존 이벤트(`PlayerData.OnInventoryChanged`, `CraftingController.CraftStarted/CraftFinished`)를 `TutorialFlow`에 전달하고 `TutorialPopup`에 문구를 보여 준다. 상점·저장·설정 UI는 컨트롤러에 "허용 여부"만 묻는다.

**Tech Stack:** Unity 6 (6000.3.27f2), C# 9, uGUI, ScriptableObject, UnityMCP(`execute_code`, `manage_scene`, `read_console`).

**Spec:** `docs/Tutorial.md` (확정). 상위 계획 `docs/V2.md`.

## Global Constraints

- 네임스페이스는 폴더와 맞춘 block style(`namespace X { }`), C# 9(file-scoped namespace 불가). 새 폴더 `Assets/Scripts/Tutorial/` → `BlackSmith.Tutorial`. UI 스크립트는 `Assets/Scripts/UI/` → `BlackSmith.UI`.
- private 필드 camelCase, 직렬화는 `[SerializeField]`, 클래스·메서드 PascalCase. 새 Singleton/전역 상태 금지.
- 글자가 있는 버튼은 `ButtonLabelPress`를 붙인다(`Label` 자식 `Text`, 평소 위치 위로 +20 비례, 눌림 위치 (0,0), `SpriteSwap`).
- 폴더 `Assets/Fantasy Wooden GUI  Free`의 공백 두 칸을 그대로 쓴다. 씬 파일명은 `TItle.unity`.
- `.cs.meta`는 삭제·재생성하지 않는다. 씬은 사용자가 요청할 때만 저장한다(저장 전 사용자에게 묻는다).
- 팝업 문구·미니게임 안내 여부·팝업 디자인은 **미정**이다. 문구는 `[임시]`로 시작하는 자리표시자로 두고 임의로 확정하지 않는다.
- 값: 정답 재료 철 원석(id `1`) × 1, 레시피 `iron_sword`, 시작 지급 = 정답 재료 구매가 합(현재 100원), 완료 보상 1000원(`PlayerData.TutorialRewardMoney`), 철 원석만 구매 가능, 철검만 판매 가능, 튜토리얼 중 저장 불가, 스킵 없음.
- 커밋은 작업별 파일만 `git add`한다. `git add -A` 금지. `Assets/Settings/*`, `ProjectSettings/*`는 에디터가 자동으로 바꾸므로 제외한다. 커밋 메시지 끝에 `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. 푸시·재빌드는 요청 시에만 한다.
- 테스트 어셈블리가 없다(프로젝트 규칙: 요청하지 않은 시스템 추가 금지). 각 작업의 검증은 `execute_code`로 하고 컴파일 체크 절차를 따른다: `read_console clear` → `refresh_unity compile=request mode=force` → `refresh_unity wait_for_ready=true` → `read_console types=[error,warning]` (`WebSocket is not initialised` 메시지는 도메인 리로드 부작용).
- `execute_code`는 CodeDom(C# 6)이다: 지역 함수·`out var`·패턴 매칭 불가, `Action`/`Func` 람다 사용, `UnityEngine.Object`·`UnityEngine.UI.*`는 완전 한정.

## Review Focus

1. **판매 탭으로 철 원석을 되팔아 막힘**: 시작 지급이 100원이라 되팔면(판매가 50) 다시 살 수 없다 → 튜토리얼 중 판매 목록에는 철검만 나온다 (Task 5).
2. **튜토리얼 도중 타이틀로 나갔다 새 게임**: 세션이 버려지고 새 게임이 처음부터, 돈 100원으로 시작한다(누적 없음) (Task 2, 5).
3. **불러온 게임·옛 세이브**: `IsTutorialPending`이 false면 컨트롤러가 시작하지 않고 팝업·제한이 없다 (Task 4).
4. **구매 전에 모루 클릭**: 빈 제작 패널만 열리고 단계는 넘어가지 않는다 (Task 3).
5. **확인 버튼 연타**: 확인 조건이 아닌 단계에서는 `NotifyConfirm`이 무시되어 한 번에 두 단계가 넘어가지 않는다 (Task 3).
6. **`TutorialConfig` 에셋이 없음**: 예전처럼 튜토리얼 없이 즉시 1000원으로 시작한다 (Task 2).

### Task 3: TutorialFlow (순수 단계 진행)

**Files:**
- Create: `Assets/Scripts/Tutorial/TutorialFlow.cs`

**Interfaces:**
- Consumes: `TutorialStepData`, `TutorialCondition` (Task 1), `PlayerData.GetTotalCount` (Task 2)
- Produces:
  ```csharp
  public class TutorialFlow
  {
      public TutorialFlow(IReadOnlyList<TutorialStepData> steps, PlayerData player);
      public TutorialStepData Current { get; }   // 끝났으면 null
      public int Index { get; }
      public bool IsFinished { get; }
      public event Action StepChanged;           // 단계가 바뀔 때마다 (Start 포함)
      public event Action Finished;              // 마지막 단계 완료 시 한 번
      public void Start();                       // 0단계로 들어가 인벤토리 조건을 즉시 평가
      public void NotifyConfirm();
      public void NotifyInventoryChanged();
      public void NotifyCraftStarted();
      public void NotifyCraftFinished();
  }
  ```
  규칙: 현재 단계의 조건과 맞는 알림만 단계를 넘긴다. 새 단계에 들어가면 인벤토리 조건(HaveItem, ItemGone)을 즉시 평가한다(연쇄 진행 가능). `ItemGone`은 해당 아이템이 한 번이라도 보인 뒤 `GetTotalCount == 0`이 될 때만 충족한다.

- [ ] **Step 1: 검증 스크립트 먼저 정의** (`execute_code`, 실제 `PlayerData`와 Task 1 에셋 단계 사용). 아직 클래스가 없으므로 컴파일 실패가 Expected.
  - 시나리오 A: `Start()` 후 `Index == 0`; `NotifyCraftStarted()` → `Index == 0`(무시); `NotifyConfirm()` → `Index == 1`; 연타로 `NotifyConfirm()` 한 번 더 → `Index == 1`(확인 단계가 아님). (Review Focus 5)
  - 시나리오 B: `player.AddItem("1", 1, 등급)` + `NotifyInventoryChanged()` → `Index == 2`. `NotifyCraftStarted()` → 3, `NotifyCraftFinished()` → 4, `NotifyConfirm()` → 5. 철검을 `AddItem` 후 `NotifyInventoryChanged()` → 여전히 5, 철검을 `TryRemoveItem` 후 `NotifyInventoryChanged()` → `IsFinished == true`, `Finished` 1회 발생, `Current == null`.
  - 시나리오 C(즉시 통과): 철 원석을 먼저 가진 상태에서 1단계로 들어오면 별도 알림 없이 바로 2단계로 넘어간다.
  - 시나리오 D(ItemGone 대기): 철검이 없는 상태에서 5단계에 들어와도 `IsFinished == false`(아이템이 보이기 전에는 충족하지 않음).
  - 시나리오 E(구매 전 모루): 1단계에서 `NotifyCraftStarted()`/`NotifyCraftFinished()`가 와도 `Index == 1` 유지. (Review Focus 4)
- [ ] **Step 2: 컴파일 체크.** Expected: 검증 코드가 `TutorialFlow` 없음으로 실패 → 구현 전 상태 확인.
