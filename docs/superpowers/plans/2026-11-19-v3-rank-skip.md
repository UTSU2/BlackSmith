# v3 대장장이 등급과 단계 스킵 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 대장장이 등급(견습~명장)과 가열·열처리 스킵 장비를 만들어, 숙련된 플레이어가 제작의 일부 단계를 건너뛰고 반복 피로를 덜게 한다.

**Architecture:** 등급·스킵 규칙은 순수 C#(`BlackSmith.Rank`), 수치는 ScriptableObject, 상태는 `PlayerData`(`JsonUtility`)에 필드로 추가한다. 스킵은 `CraftStageResult`에 "고정 점수" 결과를 넣는 방식으로 제작 흐름에 끼운다. 퀘스트(출하 3단계)는 내용이 미정이라 이 계획 밖이다(맨 아래).

**Tech Stack:** Unity 6 (`6000.3.27f2`), C# 9, uGUI, Unity MCP(검증). 테스트 어셈블리가 없으므로 순수 로직은 `execute_code`(CodeDom, C# 6)로 단언하고 화면은 플레이 모드에서 확인한다.

**Spec:** `docs/superpowers/specs/2026-11-19-v3-rank-skip-design.md`

## Global Constraints

- 등급 순서와 이름: 견습 → 초급 → 숙련 → 장인 → 명장. 시작은 견습(튜토리얼 클리어가 조건). 옛 세이브는 견습.
- 승급 조건은 도감 해금 수와 master 숙련도 수를 **각각 따로** 세며 둘 다 채워야 한다(제 해석, 설계 문서의 "정해 둔 것"으로 확인받을 것). 필요 개수는 **미정**: 에셋 기본값 `-1` = 미정 = 승급 불가.
- 숙련 등급에서 가열(1단계) 스킵 장비, 명장 등급에서 열처리(3단계) 스킵 장비. 명장은 둘 다 쓴다. 초급·장인 혜택은 미정(만들지 않는다).
- 스킵 장비: 켜기/끄기, Lv1~5, 스킵 단계 고정 점수 Lv1 5 / Lv2 6 / Lv3 7 / Lv4 8 / Lv5 9. 강화 비용은 **미정**(기본값 `-1` = 강화 불가). 장비 지급 직후 Lv1, 켜짐.
- 스킵한 제작도 총점으로 숙련도를 쌓는다. 숙련도·품질 규칙(`docs/V2.md` §2)은 바꾸지 않는다.
- 기존 `CraftStageResult.Skipped`("구현되지 않아 건너뜀, 0점")는 그대로 둔다. 새 개념은 별도(고정 점수)다.
- 네임스페이스는 `Assets/Scripts/Rank` → `BlackSmith.Rank`, 블록 스타일 `namespace X { }`. 직렬화 enum 값은 정수로 저장되므로 순서를 바꾸지 않는다.
- 세이브 필드는 `PlayerData`에 추가만 한다. `SaveFile.CurrentVersion`은 1 유지. `.cs.meta`는 지우거나 다시 만들지 않는다.
- 글자가 있는 버튼은 모두 `ButtonLabelPress`를 붙인다(CLAUDE.md "UI Buttons"). 새 시스템은 Singleton을 늘리지 않는다.
- 변경 후 CLAUDE.md "Unity MCP" 절차(컴파일 → Missing Script/참조 → 콘솔)로 확인하고, 확인한 것과 못 한 것을 보고한다. 커밋은 사용자가 승인한 뒤에만 한다.

## Review Focus

1. 옛 세이브(등급·스킵 필드 없음)를 불러오면 견습, 장비 없음, 에러 없음. → Task 2, 4
2. 이미 숙련 이상인 세이브를 다시 불러와도 스킵 장비가 중복 지급되거나 강화 단계가 초기화되지 않음. → Task 4
3. 스킵을 켠 채 레시피 `stages`에 그 단계가 없으면 아무 영향이 없음. → Task 5
4. 스킵을 쓴 제작은 최상품(40)이 나올 수 없음: 가열 Lv5 + 나머지 만점 = 39, 둘 다 Lv5 = 38. → Task 5
5. 필요 개수·강화 비용이 `-1`(미정)이면 승급·강화가 일어나지 않고 돈이 줄지 않음. → Task 1, 4, 6
6. 튜토리얼 중에는 등급 표시와 스킵 모두 없음. 타이틀로 나갔다 새 게임을 하면 등급 초기화. → Task 3, 5

### Task 1: 등급 데이터와 규칙

**Files:**
- Create: `Assets/Scripts/Rank/BlacksmithRank.cs`, `BlacksmithRankSettings.cs`, `BlacksmithRankRules.cs`
- Create asset: `Assets/Resources/Rank/BlacksmithRankSettings.asset`

**Interfaces:**
- Produces:
  - `enum BlacksmithRank { Apprentice = 0, Novice = 1, Skilled = 2, Artisan = 3, Grandmaster = 4 }` (견습/초급/숙련/장인/명장)
  - `BlacksmithRankSettings : ScriptableObject` — `const string ResourcePath = "Rank/BlacksmithRankSettings"`, `static BlacksmithRankSettings Load()`, `string GetName(BlacksmithRank)`, `int GetRequiredCodex(BlacksmithRank target)`, `int GetRequiredMasters(BlacksmithRank target)` (target = 오르려는 등급, 견습은 -1, 필요 개수 `-1` = 미정)

  - `class BlacksmithRankRules` — `BlacksmithRankRules(BlacksmithRankSettings settings)`, `RankProgress Evaluate(BlacksmithRank current, int codexCount, int masterCount)`

- [ ] **Step 1: 에셋 먼저 만들 수 있게 스크립트 3개 작성** — 위 시그니처대로. `IsMet`은 `IsDecided && Codex >= RequiredCodex && Masters >= RequiredMasters`. 명장은 `HasNext=false`. 설정 에셋의 이름 기본값은 견습/초급/숙련/장인/명장, 필요 개수 기본값은 모두 `-1`.
- [ ] **Step 2: 컴파일** — `read_console clear` → `refresh_unity compile=request mode=force` → `refresh_unity wait_for_ready=true` → `read_console types=[error,warning]`. 기대: 에러 0.
- [ ] **Step 3: 에셋 생성** — `Resources/Rank/BlacksmithRankSettings.asset`(Create > 또는 `manage_scriptable_object`). 값은 기본값 그대로(필요 개수 전부 `-1`).
- [ ] **Step 4: 규칙 검증** — `execute_code`로 임시 `BlacksmithRankSettings`(`ScriptableObject.CreateInstance`, `SerializedObject`로 숙련 목표를 해금 10·master 2로 설정)를 만들어 단언: `Evaluate(Apprentice, 0, 0).IsDecided == false`(미정), `Evaluate(Apprentice,10,2)`(필요 개수 -1이면) `IsMet == false`; 설정 후 `Evaluate(Novice, 10, 1).IsMet == false`(master 부족), `Evaluate(Novice, 10, 2).IsMet == true`, `Evaluate(Grandmaster, 99, 99).HasNext == false`. 기대: 모두 참.
