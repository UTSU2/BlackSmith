# 정밀 밸런스 설계 (v2 5번, 짧은 설계)

작성 2026-11-18. 상위 문서: `docs/V2.md` §5 "정밀 밸런스", `docs/GameDesign.md` §5 가격.

## 의도
한 번 제작의 수익률이 품질로만 정해져 등급과 관계없이 같다(−30 / 0 / +20 / +50 / +100%). 높은 등급 레시피를 찾아 만들 이유가 작다. 등급에 비례해 수익률을 높인다.

## 목표 (사용자 결정)
- 완성품 판매가 = 재료 구매가 합 × 품질 배율 × (품질이 **상품 이상**이면 완성품 등급 배율). 등급 배율: Common 1, Uncommon 1.1, Rare 1.3, Unique 1.7, Legendary 2.5. 최하품·하품·중품에는 곱하지 않는다.
- 광물 구매가: Common 100(그대로) / Uncommon 180 / Rare 350 / Unique 720 / Legendary 1200. 되팔기는 구매가의 절반(90 / 174 / 360 / 600; Rare는 반올림 때문에 175 대신 174).
- 범위는 이 가격 변경까지. 숙련도 성장·시작 자금·제작 시간은 바꾸지 않는다.

## 비목표
- 레시피 재료 구성 변경(v3), 숙련도·난이도·제작 시간 조정, 알 수 없는 제작품 가격(50 고정 유지), 튜토리얼 지급금(철 원석 100 기준, 그대로).

## 방식 검토
| 안 | 내용 | 평가 |
|---|---|---|
| **A. 판매 시 계산 (채택)** | `CraftedItemData.GetSellUnitPrice`에서 변형(등급·품질)으로 등급 배율을 곱한다. 배율 표는 `ItemGradeInfo`에(품질 배율처럼 코드 상수). | 옛 세이브 아이템에도 적용, 저장 형식 변화 없음. 반올림은 마지막 한 번. |
| B. 제작 시 저장 | 등급 배율을 곱한 값을 `ingredientValue`에 저장 | 옛 아이템과 가격이 달라지고 의미가 섞임. |

광물 가격은 공식(`Common 기준가 × 등급 가격 배율`)을 유지하고 광물마다 Common 기준가만 바꾼다: 구매 150 / 233 / 400 / 600, 되팔기 75 / 116 / 200 / 300 (Uncommon / Rare / Unique / Legendary).

## 빌더 몫
- 메서드 이름, 계산 순서(decimal로 곱한 뒤 `PriceRounding.Round` 한 번).
- 이미 가진 완성품은 저장된 재료 합산 가격(옛 광물 가격 기준)에 새 배율이 적용된다. 별도 이전 처리는 하지 않는다.
