# v3 설계 — 대장장이 등급과 단계 스킵

> **상태: 초안, 승인 대기** (2026-11-19). 아래 **[미정]**은 사용자가 정하며 임의로 정하지 않는다.

## 의도

같은 제작을 반복하면 지치므로, 제작 시간이 길다는 불만을 덜어 준다. 처음에는 모든 단계를 직접 하고, 플레이어가 성장(대장장이 등급)하면 일부 단계를 건너뛸 수 있는 장비를 받는다. 모든 단계를 건너뛰지는 않는다. (v2의 원래 목적 "반복 제작의 피로 완화"를 v3 목적으로 되돌린다.)

## 목표 / 비목표 / 안티목표

- **목표:** 등급 시스템, 단계 스킵 장비(가열, 열처리), 등급 승급 퀘스트. 제작 시간 20초 중 숙련 등급에서 5초, 명장 등급에서 7초를 줄인다.
- **비목표:** 모든 단계 생략(자동 완료), 일반 퀘스트 시스템, 레시피 49종의 재료 구성 조정(별도 작업), 장비 강화(v2 제외 유지), 초급·장인 등급의 혜택(미정).
- **안티목표:** 스킵만으로 최상품(40점)을 만들 수 있게 되는 것. 튜토리얼 흐름이 바뀌는 것. 기존 세이브가 깨지는 것.

## 제약

- 세이브는 `PlayerData`(`JsonUtility`)에 필드를 추가하는 방식이며, 옛 세이브는 필드 없음 = 기본값으로 읽힌다. `SaveFile.CurrentVersion`은 1을 유지한다.
- 숙련도·품질 규칙(`docs/V2.md` §2): 총점 20점 미만은 숙련도 없음, 보너스 적용 후 총점 상한 39(40은 직접 만든 원점수 40만). 이 규칙은 바꾸지 않는다.
- 기존 `CraftStageResult.Skipped`는 "구현되지 않아 건너뜀, 0점"이라는 다른 뜻이다. 새 개념과 섞이지 않게 별도 표현(고정 점수)을 둔다.
- 데이터는 ScriptableObject, 로직은 순수 C#, 프레젠터는 UI(기존 아키텍처 규칙).
- 레시피 `stages`에 해당 단계가 없으면 스킵은 적용되지 않는다.

## 접근 방식

- **A. 단계별 출하 (선택).** 등급 → 스킵 장비 → 퀘스트 순으로 나눠 만든다. 단계마다 확인하고 push할 수 있고, 미정인 퀘스트 내용이 앞 단계를 막지 않는다. 퀘스트가 붙기 전까지 승급은 개발용 임시 처리다.
- B. 범용 퀘스트 시스템 먼저: 확장성은 좋지만 퀘스트 내용이 미정이라 쓰지 않을 기능을 만들 위험이 크다.
- C. 등급 전용 단순 퀘스트: 가장 빠르지만 일반 퀘스트로 넓힐 때 구조를 다시 짠다.

## 확정된 규칙

**등급**
- 순서: 견습 → 초급 → 숙련 → 장인 → 명장. 시작은 견습이며 견습의 조건은 튜토리얼 클리어다. 옛 세이브는 튜토리얼을 마친 것으로 보므로 견습이다.
- 승급 조건: 등급마다 **도감 해금 수**와 **master 숙련도 수**를 각각 따로 센다. 필요 개수는 **[미정]**(에셋에서 사용자가 채운다).
- 승급 흐름: 개수 조건 충족 → 퀘스트를 받을 수 있음 → 퀘스트 클리어 → 등급 상승.
- 퀘스트의 내용(무엇을 하면 클리어인가)은 **[미정]**. 퀘스트 부여는 예정된 기능이다.

**혜택**
- 숙련: 가열(1단계) 스킵 장비를 준다.
- 명장: 열처리(3단계) 스킵 장비를 준다. 가열 스킵도 계속 쓸 수 있다.
- 초급, 장인: 혜택 **[미정]**.

**스킵 장비** (가열용과 열처리용, 각각)
- 켜기/끄기가 가능하다. 끄면 그 단계를 직접 한다.
- 재화를 써서 5단계까지 강화한다. 비용은 **[미정]**.
- 켠 상태에서 제작하면 그 단계의 미니게임을 하지 않고 **고정 점수**가 들어간다: Lv1 5점, Lv2 6, Lv3 7, Lv4 8, Lv5 9. 최대 9점이므로 스킵을 쓰면 40점이 나올 수 없다.
- 합계 상한: 가열 스킵만 쓰면 39, 두 스킵을 모두 쓰면 38.
- 스킵한 제작도 총점에 따라 숙련도를 쌓는다(`docs/V2.md` §2의 규칙 그대로, 20점 미만은 없음).
- 튜토리얼 제작에는 스킵이 없다(견습은 장비가 없다).

## 정해 둔 것 (제 선택, 사용자 확인 필요)

- 장비를 받은 직후의 강화 단계는 Lv1(5점), 장비는 받으면 켜진 상태. 켜기/끄기 UI는 제작 패널 시작 버튼 근처에 둔다.
- 등급 이름 "초급"은 숙련도 단계 이름(초급·중급·고급)과 겹친다. UI에 "대장장이 등급" 라벨을 붙여 구분한다. 이름을 바꿀지는 사용자가 정한다.
- 등급과 승급 조건, 혜택은 ScriptableObject(`BlacksmithRankSettings`, 등급별 조건·퀘스트 id·혜택)에 두고 규칙 계산은 순수 C#(`BlacksmithRankRules`)에 둔다.
- 세이브 추가 필드: 현재 등급, 퀘스트 진행 상태, 스킵 장비별(보유 여부, 강화 단계, 켜짐 여부).

## 출하 계획

1. **등급 기반** — `PlayerData` 등급 필드, 설정 에셋, 규칙(해금 수·master 수 계산), HUD 표시와 승급 진행도. 승급은 개발용으로 조건 충족 시 바로 오른다(퀘스트 단계에서 제거).
2. **스킵 장비** — 장비 데이터·세이브, 숙련/명장 승급 시 지급, 켜기/끄기, 재화 강화, 제작에서 단계 생략과 고정 점수 반영(`CraftingController`, `CraftScoring`), 결과 팝업·로그에 스킵 표시.
3. **퀘스트** — 승급 퀘스트 에셋과 진행·클리어, 승급 연결(임시 처리 제거).

## 미정 (사용자가 정함)

- 등급별 필요 개수(도감 해금 수, master 수)
- 승급 퀘스트의 내용과 개수, 퀘스트 UI
- 초급·장인 등급의 혜택
- 스킵 장비의 강화 비용과 장비 이름·아이콘·UI 비주얼
- 등급 이름이 숙련도 단계 이름과 겹치는 문제

## 빌더에게 맡기는 부분

클래스 분리와 파일 배치, 설정 에셋의 필드 구성, 켜기/끄기·강화 UI의 구체 배치, 세이브 필드 이름. Unity 검증은 CLAUDE.md 절차(컴파일, Missing Script, 콘솔, 플레이 확인)를 따른다. 테스트 어셈블리는 없다.
