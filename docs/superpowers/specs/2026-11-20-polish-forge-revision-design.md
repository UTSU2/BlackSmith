# 연마 검 축소·흠집 개선 + 단조 주괴·망치 설계

작성 2026-11-20. 앞선 설계: `2026-11-20-polish-weapon-design.md`(연마 검/숫돌), `2026-11-20-minigame-art-stage2-design.md`(단조 원). 플레이 확인 뒤 사용자 피드백:

1. 연마: 검이 너무 크다. 갈색 오브젝트가 흠집이라는데 흙이 묻은 것처럼만 보인다.
2. 단조: 아무것도 없는데 치는 이펙트만 나온다. 광물 주괴 이미지를 만들어 그 위에서 망치로 치는 것처럼 하고 싶다.

사용자 결정(질문 답변): 연마 검은 **끝까지 보이는 통통한 검**, 단조 주괴는 **달궈진 주괴 1종**, 망치는 **클릭 지점에 내리찍는 망치**.

## 의도

- 연마는 "검의 흠집을 숫돌로 갈아내는" 장면이 한눈에 읽혀야 한다. 흠집은 흙이 아니라 **긁힘·찍힘·패임**으로 보여야 하고, 갈아낼수록 사라져야 한다.
- 단조는 "달궈진 주괴를 망치로 두드리는" 장면이어야 한다. 원은 주괴 위에 나타나고, 정확히 누르면 그 지점을 망치가 내리친다.

## 목표 / 비목표

- 목표
  - 연마: 검 전체(손잡이~끝)가 화면 안에 보이고 지금보다 확실히 작다. 흠집은 긁힘/찍힘/패임 3종으로 틴트 없이도 흠집으로 읽힌다. 문지르기 규칙·난이도는 그대로.
  - 단조: 화면 중앙에 달궈진 주괴가 있고 원은 주괴 위에서만 생긴다. 판정된 클릭(Perfect/Good/눌러서 Miss)마다 그 지점에 망치가 내리찍는다. 판정 규칙·난이도는 그대로.
- 비목표: 판정·점수·난이도·시간·개수 변경, 광물별/등급별 주괴, 무기 종류별 검, 힛 이펙트 프리팹 구조 변경, `PlayArea` 배경 이미지 교체, 효과음 변경, 놓친 Miss(누르지 못함)에 망치 표시.
- 안티 목표: 흠집이 날 밖으로 나가거나 크게 겹침 / 원이 주괴 밖에 생김 / 망치가 다음 원을 가려 입력을 막음(raycast 끔) / 기본 설정에서 기존 동작이 달라짐 / 로직이 이미지·씬 좌표를 앎.

## 현재 구조 (조사)

- 연마(2026-11-20 직전 작업): `PlayArea`는 1600×900(1유닛 = 100px), 검 `Blade` 1950×617(날 두께 5.6유닛, 오른쪽이 화면 밖), 흠집 지름 1.8유닛(180px), 흠집은 `spawnArea = Rect(4.4,3.0,10.7,3.0)` 안에 생김. 흠집 스프라이트 3종은 모두 원형으로 꽉 찬 얼룩이고 뷰가 갈색(0.55,0.25,0.1)/주황(0.9,0.45,0.15)을 곱한다.
- 단조: `ForgeSettings`에 `margin`(기본 2)만 있고, 원은 `[margin, AreaSize − margin]`(x 2~14, y 2~7)에서 뽑는다. `PickPosition(index)`는 **바로 앞 원과** `targetRadius × 3`(2.4) 이상 떨어지게 최대 20번 재시도한다. 목표 원 반지름 0.8, 줄어드는 원 시작 반지름 2.0. 난이도 10은 18개, 간격 0.3초. `ForgeMinigame.CircleJudged(Circle)`에 `Clicked`가 있다(눌러서 판정됐는가). 뷰는 `ForgeMinigameView`.

## 설계

### A. 연마

1. **검 이미지 다시 생성** (gpt-image, edit 모드로 이전 `polish_blade` 기반 가능). 손잡이는 왼쪽, **날 끝(뾰족한 끝)이 오른쪽에 보이는** 통통한 롱소드(전체 비율 약 3.5:1, 날 두께가 이미지 높이의 약 85%). 기존 스타일 유지.
2. **크기: `PlayArea` 전체를 80%로 줄인다 (1600×900 → 1280×720)**. 게임 공간(16×9)은 그대로이고 1유닛 = 80px이 된다. 뷰가 `playArea.rect.width / 16`로 환산하므로 흠집·입력·이펙트가 함께 줄고 규칙은 안 바뀐다. 검은 게임 단위로 배치한다: 손잡이 끝 ≈ x 0.1, 가드 ≈ 2.5, 날 직선 구간 2.5~14.7, 끝 ≈ 15.9, 날 두께 약 4.0~4.5유닛 → 화면에서 날 두께 약 320~360px(화면 높이의 30~33%), 전체 폭 약 1270px. (현재 날 두께 560px, 폭이 화면 전체.) 80%는 제 판단이고 조정 가능하다.
3. **흠집 이미지 3종 교체**: 원형 얼룩이 아니라 **표시 사이사이가 투명한** 이미지로 만든다. 모두 무채색, 외곽선 없음, 정사각, 흠집 영역(반지름 0.9)에 맞게 꽉 참.
   - `polish_flaw_scratch`: 깊고 굵은 긁힘 몇 줄 + 가는 긁힘, 금속이 드러난 밝은 가장자리.
   - `polish_flaw_dent`: 찍힌 자국 — 가운데 패임과 방사형 금.
   - `polish_flaw_pit`: 부식으로 파인 작은 점들의 무리.
   기존 `polish_flaw`(녹 얼룩)는 `flawSprites`에서 빼고 새 `polish_flaw_pit`으로 대체한다 (파일은 남겨도 됨).
4. **색 조정 (뷰의 직렬화 값)**: `flawColor`를 갈색에서 중립 어두운 회색 (0.85,0.85,0.9,1)로, `activeFlawColor`를 따뜻한 주황 (1,0.6,0.35,1)로 바꾼다 (문지르는 중임을 알리는 용도). 남은 양에 따른 알파(0.25~1) 감소는 그대로라 갈수록 흠집이 옅어진다.
5. **흠집 생성 영역 재설정** (`spawnArea`, 게임 단위): x = 가드 + 반지름 ~ 날 직선 끝 − 반지름, y = 날 두께 − 지름. 6개가 겹치지 않아야 하므로 측정해서 정한다 (기준: 난이도 10, 씨드 1000판에서 원이 겹친 판 ≤ 3%, 최악 최소 거리 ≥ 1.5, 날 밖으로 나간 원 0개).
6. 숫돌: 크기를 새 `PlayArea` 비율에 맞게 줄인다(210×79 → 약 170×64). 그 외 숫돌 동작은 그대로.

### B. 단조

1. **로직: 원 생성 영역** (`BlackSmith.Crafting`): `ForgeSettings`에 `Rect spawnArea = new Rect(2, 2, 12, 5)` 추가(게임 단위, 원 중심이 놓일 수 있는 영역, 기본값은 현재 동작과 같음). `PickPosition`은 `margin` 대신 `spawnArea`를 쓴다(폭/높이 ≤ 0이면 중앙). 난수 순서·재시도(20회, 바로 앞 원과의 간격)·판정은 그대로이므로 기본 영역 결과는 예전과 같아야 한다. `margin`은 남기고 쓰지 않는다. 씬의 `CraftingController.forgeSettings.spawnArea`는 주괴 윗면에 맞춰 설정한다.
2. **주괴 이미지** (gpt-image, 스타일 기준 `heat_bar_frame.png`/기존 배경 그림체): 가로로 놓인 사다리꼴 주괴, 달궈진 주황빛(가열 직후), 윗면이 넓게 보이는 약간 비스듬한 정면 뷰, 투명 배경. 윗면에 원이 놓이므로 윗면이 평평하고 넓어야 한다.
3. **망치 이미지**: 대장장이 망치, 옆모습, 머리가 아래 왼쪽, 손잡이가 오른쪽 위로 비스듬(약 45°), 투명 배경, 만화풍 외곽선.
4. **뷰 (`ForgeMinigameView`)**: `[SerializeField] RectTransform hammer`와 (선택) `ingot`을 추가한다.
   - 망치: `CircleJudged`에서 `circle.Clicked`가 true이면 그 원의 위치에서 짧은 내리찍기 애니메이션(들어올린 각도 → 내리침 → 잠깐 정지 → 사라짐, 총 약 0.2초)을 재생한다. 놓친 Miss(`Clicked == false`)에는 재생하지 않는다. 망치 하나를 재사용하고 새 클릭이 오면 처음부터 다시 재생한다(난이도 10은 0.3초 간격). 이펙트(`HitEffectSpawner`)는 지금처럼 판정 즉시 재생한다.
   - 주괴(선택): 판정 클릭 때 아주 짧게 눌렸다 돌아오는 스케일 반응(예: 0.97 → 1, 0.08초).
   - 망치·주괴 이미지는 `raycastTarget = false`. 망치는 원 위, 힛 이펙트(UI 정렬 10) 아래.
   - 모든 애니메이션은 뷰의 `Update`가 시간으로 진행한다(코루틴 불필요). `Show`/`Hide`/`Clear`에서 망치를 숨기고 상태를 초기화한다.
5. **씬 (`ForgePanel/PlayArea`)**: `Ingot`(맨 뒤, 가운데)과 `Hammer`(비활성, 피벗은 머리 타격면에 맞춤)를 추가하고 뷰에 연결한다. `forgeSettings.spawnArea`를 주괴 윗면 안쪽(목표 원 반지름 0.8이 윗면 밖으로 안 나가게)으로 설정한다.

## 접근 방식

| 결정 | 선택 | 이유 |
|---|---|---|
| 검 축소 | 끝까지 보이는 통통한 검 + `PlayArea` 80% | 사용자 선택. 흠집 지름이 커서 실제 비율 검은 흠집이 날 밖으로 나감. `PlayArea` 축소는 규칙을 안 바꾸고 전체를 같이 줄임. |
| 흠집 모양 | 표시만 있는 투명 이미지 3종 | 원형 얼룩이 흙으로 읽히는 원인 제거. 갈수록 옅어지는 알파가 "갈려서 사라짐"으로 읽힘. |
| 주괴 | 달궈진 주괴 1종 | 사용자 선택. 광물별은 48종이라 보류. |
| 망치 | 클릭 지점 내리찍기(판정된 클릭에만) | 사용자 선택. 포인터 추종은 원을 가려 미채택. |
| 원 생성 영역 | `ForgeSettings.spawnArea` | 연마와 같은 방식, 기본값 불변, 로직은 이미지를 모름. |

## 판단 (확인 필요)

- `PlayArea` 80% (1280×720)와 검 전체 폭 약 1270px.
- 흠집 틴트: 기본 (0.85,0.85,0.9) 회색, 문지르는 중 (1,0.6,0.35) 주황.
- 망치 애니메이션 총 0.2초, 주괴 눌림 0.97배 0.08초.
- 단조 주괴 윗면에 원이 6~18개 들어가야 하므로 주괴는 넓게(약 11유닛 × 윗면 4.5유닛) 만든다.

## 결과 (2026-11-20)

### 연마
- 검: 이전 확대 구도를 버리고 날 끝(뾰족한 끝)까지 보이는 통통한 롱소드로 재생성(edit 모드, 2165×615, 날 두께 556px, 날 직선 구간 가드 오른쪽 x≈415 ~ 1900, 끝 2165). `polish_blade.png`를 같은 경로에 덮어씀(GUID 유지).
- `PolishPanel/PlayArea` = 1280×720(80%, 1유닛 = 80px). `Blade` 1423.7×404.4, 위치 (−1.05, 0): 가드 오른쪽이 게임 x 2.5, 날 직선 끝 14.7, 날 두께 약 4.57유닛(화면 366px). 화면 x 247~1671(전체 폭의 74%)로 이전(두께 560px, 화면 폭 전체)보다 확실히 작다. 오른쪽 끝(날 끝)과 왼쪽 폼멜이 화면 안에 있다.
- 흠집 3종 교체: `polish_flaw_scratch`(굵은 긁힘 + 가는 긁힘), `polish_flaw_dent`(찍힌 패임 + 방사형 금), 새 `polish_flaw_pit`(부식 점 무리). 모두 표시 사이가 투명, 무채색, 외곽선 없음, 512. 기존 `polish_flaw`(녹 얼룩)는 `flawSprites`에서 뺐다(파일은 남김). 틴트: `flawColor` (0.85,0.85,0.9), `activeFlawColor` (1,0.6,0.35).
- `polishSettings.spawnArea` = `Rect(3.4, 3.2, 10.4, 2.6)`. 숫돌 170×64.
- 검증: 난이도 1/5/10, 씨드 1000판씩 — 날 직선 구간 밖으로 나간 흠집 원 0개, 겹친 판 0판, 난이도 10 최악 최소 거리 1.83(겹침 기준 1.8).

### 단조
- 로직: `ForgeSettings.spawnArea`(기본 `Rect(2,2,12,5)` = 예전 동작). 같은 씨드에서 기본 영역의 원 위치가 예전 알고리즘(여백 2, 20회 재시도)과 12000개 모두 같음을 확인. 비정상 영역은 중앙. 8×1.8유닛 영역에서도 연속한 원 간격 ≥ 2.4가 100%라 주괴 표면을 계획(11×4.5)보다 작게 쓸 수 있었다.
- 이미지(`Assets/Sprites/Minigame/Forge/`): `forge_ingot`(2134×666, 달궈진 주황빛 사다리꼴 주괴, 윗면과 앞면이 보임), `forge_hammer`(1243×1243 → 임포트 1024, 머리가 왼쪽 아래, 타격면 피벗 (0.15, 0.04)).
- 뷰(`ForgeMinigameView`): `hammer`, `ingot` 필드와 튜닝 값(들어올림 각도 35°·오프셋 (50,80), 내리침 0.05초, 정지 0.06초, 사라짐 0.09초, 주괴 0.97배 0.08초). 눌러서 판정된 클릭(`Clicked == true`)에만 망치가 그 원 위치를 내리찍고, 이펙트는 그대로 판정 즉시 재생. 새 클릭이 오면 처음부터 다시 재생. `Show`/`Hide`/끝에 망치를 숨기고 주괴 스케일을 복원. 이미지 `raycastTarget`은 코드가 끈다.
- 씬(`ForgePanel/PlayArea`): `Ingot`(맨 뒤, 1400×437, 가운데), `Hammer`(비활성, 440×440). `forgeSettings.spawnArea` = `Rect(3.65, 3.67, 8.57, 1.68)` (주괴 표면 안쪽, 목표 반지름 0.8만큼 안으로).
- 검증: 난이도 1/5/10, 씨드 500판씩 — 원 중심이 모두 영역 안, 연속 원 간격 ≥ 2.4가 100%. 편집 모드에서 실제 `ForgeMinigame` 이벤트로 시험: 놓친 Miss는 망치 없음, 눌러서 판정되면 망치 활성(경과 0), +0.06초에 주괴 0.974배, 두 번째 타격은 처음부터 재시작, +0.5초 뒤 망치 숨김·주괴 1.0·알파 1, 타격 중 `Hide`도 정리, `hammer`/`ingot` 필드를 비워도 예외 없음(시험 중에는 `hitEffects`만 잠시 비웠다가 복원).
- 렌더링(Game 캔버스 카메라): 주괴 위 원 4가지 상태와 줄어드는 링, 망치 내리찍기 6프레임(들어올림 → 타격 → 정지 → 사라짐).
