# 레시피 습득 설계 (v2 4번)

작성 2026-11-18. 대상 문서: `docs/V2.md` §3 "레시피 습득". 이 문서는 §3의 확정 결정에 2026-11-18 브레인스토밍 결정(도감 화면·번호·알림·경로)을 더해 구현 범위를 정한다.

## 의도

v2의 주 목적 중 하나는 **레시피 습득으로 도감 수집 욕구를 자극하는 것**이다. 지금(v1)은 넣은 재료와 가장 가까운 레시피가 자동으로 골라지고 레시피는 플레이어에게 보이지 않는다. 이 단계에서:

- 재료 조합을 직접 시도해 레시피를 찾는 **실험 자체를 재미**로 삼는다. 단서는 주지 않는다.
- 찾은 레시피는 **도감**에 남아 재료 구성과 숙련도를 다시 볼 수 있다.
- 맞지 않는 조합은 **알 수 없는 제작품**(판매가 50골드 고정)이 되어 손해를 본다.

## 목표 (사용자 결정)

**매칭**
- 정확 일치만 레시피로 인정한다. 기준은 **재료 종류 + 수량**(등급 무관). v1 점수제 매칭은 폐지한다.
- 투입한 재료는 지금처럼 제작 시작 시 모두 소모된다.

**알 수 없는 제작품**
- 일치하는 레시피가 없으면 "알 수 없는 제작품"이 나온다. Common, 아이템 ID `999`, 아이콘 **[미정]**(자리표시자).
- 판매가는 품질과 관계없이 **50골드 고정**. 미니게임 난이도 **2 고정**. 품질은 미니게임 점수로 정해지지만 가격·숙련도에 영향 없음.
- **레시피가 아니다**: 레시피 목록·도감·숙련도에 들어가지 않는다. 도감 번호 없음.
- 거치는 단계: 4단계 모두(가열·단조·열처리·연마). 49개 레시피가 모두 4단계라 같은 흐름을 쓴다. (설계자 제안, 사용자 확인 대상)

**도감**
- 저장 버튼 옆의 새 버튼으로 여는 UI 패널.
- **해금:** 레시피를 제작 완료하면 해금(품질 무관, 최하품도 해금). 경로는 **실험(직접 제작)뿐**이다. 상점 구매·보상 같은 다른 경로는 v2에서 만들지 않는다.
- **진행도:** "해금 n / 49"(전체 레시피 수 기준, 알 수 없는 제작품 제외)와 진행 막대.
- **배치 (시안 A):** 7×7 격자 + 오른쪽 상세 영역. 칸을 누르면 상세가 바뀐다.
- **모르는 칸:** 번호와 `???`만 보인다.
- **해금한 칸:** 아이콘(격자), 상세에는 번호·완성품 이름·등급·**재료 구성(재료와 수량)**·숙련도(단계·레벨, 진행도 수치+막대, 품질 보너스).
- **순서:** 레시피마다 새 필드 **도감 번호**(1부터)를 두고 그 순서로 놓는다. 등급이 낮은 완성품이 앞 번호를 받는다. 번호는 **Recipe Creator에서 직접 입력**하고, 창은 번호 중복·등급 순서 위반을 경고한다.
- **저장은 레시피 id 기준:** 해금 기록은 영어 레시피 id(`recipe_iron_axe` 등)로 저장한다. 도감 번호는 표시·순서에만 쓴다. 새 레시피가 끼어 번호가 밀려도 해금이 엉뚱한 칸으로 옮겨 가지 않는다.
- **옛 세이브:** 도감 필드가 없는 세이브는 `PlayerData.proficiencies`에 기록이 있는 레시피를 해금한 것으로 채운다. (숙련도는 20점 이상 제작만 기록되므로 그 밖의 과거 제작은 해금되지 않는다. 사용자 확인함)

**해금 알림**
- 처음 만든 레시피면 기존 제작 결과 팝업에 "새 레시피 해금 (No.n)" 줄을 보인다. 새 팝업은 만들지 않는다.
- 알 수 없는 제작품이면 같은 결과 팝업에 숙련도 줄 없이 이름·등급·품질과 판매가 50골드를 보인다. (설계자 제안)

**콘텐츠**
- 레시피 49종은 v2에서 완성이다. 재료 구성 조정(밸런스)은 v3. 새 아이템은 알 수 없는 제작품 1종뿐.
- 49종의 도감 번호 초기값은 구현 시 **임시로** 채운다: 결과 등급순 → 같은 등급 안에서는 현재 레시피 id 글자순. 사용자가 이후 Recipe Creator에서 고친다. (등급별 개수: Common 19 → 1–19, Uncommon 12 → 20–31, Rare 9 → 32–40, Unique 6 → 41–46, Legendary 3 → 47–49)

## 비목표

- 도감을 채우는 실험 외 경로(상점 레시피 판매, 보상).
- 레시피 재료 구성 변경, 레시피·아이템 추가(999 제외), 밸런스 조정(v3).
- 단서·힌트·미리보기(넣은 재료로 무엇이 나올지 알려 주는 표시).
- 도감 패널의 최종 비주얼(스프라이트, 색, 글꼴 크기). 배치만 확정이고 모양은 임시값.
- 알 수 없는 제작품 최종 아이콘(**[미정]**).
- 튜토리얼 문구 확정(사용자가 직접 쓴다).

## 하면 안 되는 것 (실패 조건)

- **제작 전에 조합이 레시피인지 드러난다.** 지금 제작 패널의 상태 문구는 "제작할 수 있습니다 / 조합이 맞지 않습니다"로 매칭 여부를 알려 준다. 정확 일치 도입 후 이 문구가 그대로면 실험 없이 정답을 찾을 수 있다. 재료가 하나 이상이면 레시피 여부와 관계없이 같은 문구·같은 시작 버튼 상태여야 한다.
- 알 수 없는 제작품이 도감 칸·진행도 분모·숙련도에 들어간다.
- 도감 번호가 바뀌었을 때 해금 기록이 다른 레시피로 옮겨 간다.
- 옛 세이브를 불러왔을 때 숙련도 기록이 있는 레시피가 잠겨 있거나, 해금 목록이 불러올 때마다 다시 덮어써진다.
- 튜토리얼(철 원석 ×1 → 철검)이 정확 일치 도입 후 흐름이 깨진다.

## 방식 검토 (알 수 없는 제작품 표현)

| 안 | 내용 | 평가 |
|---|---|---|
| **A. 별도 설정 데이터 (채택)** | `Resources`에 "레시피 없는 제작" 설정 에셋 1개(결과 아이템 999, 단계 목록, 난이도 2). 고정 판매가는 완성품 아이템 데이터의 "고정가" 필드(0이면 기존 공식). | "레시피가 아니다"라는 결정과 구조가 같다. 레시피 목록·도감·숙련도에 섞이지 않는다. 수치가 데이터. 제작 흐름에 "레시피 또는 설정" 분기가 생긴다. |
| B. 숨긴 레시피 에셋 | 레시피 폴더에 "도감 제외" 표시 레시피 1개 | 제작 흐름은 그대로지만 레시피 수가 50이 되고 도감·숙련도·매칭·Recipe Creator가 모두 예외를 걸러야 한다. 빠뜨리기 쉽다. |
| C. 코드 상수 | 999/2/50을 코드에 고정 | 가장 빠르나 수치를 데이터로 둔다는 프로젝트 규칙에 어긋난다. |

사용자가 A를 골랐다.

## 구조 (A안)

현재 코드 기준. 기존 흐름: `CraftingPanel`(투입) → `CraftingSession.Refresh`가 `RecipeMatcher.Match`로 `Recipe`를 갱신 → `TryStart`가 `CraftScoring.CreateRequest(recipe, inputs)` → `CraftingController`가 `request.Recipe.Stages`를 진행 → `GrantResult`가 `Recipe.Result`·`Recipe.Id`로 지급·숙련도.

**매칭 (`Crafting`)**
- `RecipeMatcher.Match`: 투입 재료(아이템별 합산)와 레시피 재료(`CraftScoring.SumRecipeIngredients`)의 종류·수량이 정확히 같은 레시피만 돌려준다. 없으면 null. 두 레시피가 같은 구성이면 모호하므로(Recipe Creator가 이미 경고) 먼저 등록된 것을 쓰고 경고를 남긴다(설계자 제안).
- `CraftingSession.CanStart`: 재료가 하나 이상이면 true. `Recipe`가 null이면 알 수 없는 제작으로 시작한다.

**레시피 없는 제작**
- 새 ScriptableObject (예: `UnknownCraftSettings`, `Resources/Crafting/UnknownCraftSettings.asset`, `Load()` 패턴은 `ProficiencySettings`와 같게): 결과 `CraftedItemData`(999), 단계 목록, 기본 난이도(2).
- `CraftRequest`는 레시피 대신 "결과 아이템·단계·난이도·재료 합산 가격"을 직접 갖거나, 레시피가 null일 수 있고 결과·단계를 따로 갖는다. `CraftResult.Recipe`가 null이면 알 수 없는 제작이다. 이름과 형태는 구현 계획에서 정한다.
- `CraftingController`: 단계 진행은 요청의 단계 목록을 쓴다. `GrantResult`는 레시피가 없으면 숙련도·해금을 건너뛴다.
- `CraftedItemData`에 고정 판매가 필드(0 = 기존 `IngredientValue × 품질 배율`). 999는 50. Item Creator 창에 필드를 추가한다(창은 private 필드 이름으로 기록하므로 함께 수정).
- 설정 에셋이 없으면: 일치하지 않는 조합은 지금처럼 시작할 수 없게 한다(경고 로그). 숙련도 설정이 없을 때와 같은 방식의 안전장치.

**도감 데이터**
- `CraftRecipeData`에 `codexNumber`(int) 필드. Recipe Creator 창에 입력란과 경고(중복, 결과 등급이 더 낮은데 번호가 더 큰 경우, 0/미입력). 레시피 id를 바꾸면 해금·숙련도 기록이 끊긴다는 경고도 넣는다.
- 도감 목록은 `RecipeDatabase.All`을 `codexNumber` 순으로 정렬해 만든다.

**저장 (`Data`)**
- `PlayerData`에 해금한 레시피 id 목록(`List<string>`)과 "도감 초기화 여부" 표시. `IsRecipeUnlocked(id)`, `UnlockRecipe(id)`(새로 해금이면 true, `HasUnsavedChanges` 설정).
- 옛 세이브: 불러올 때 초기화 표시가 없으면 `proficiencies`의 레시피 id로 목록을 채우고 표시를 켠다. 한 번만 한다. 새 게임은 표시를 켠 빈 목록으로 시작한다. `SaveFile.CurrentVersion`은 1 그대로(필드 추가만).

**제작 결과에 해금 기록**
- `GrantResult`(레시피가 있을 때): 지급 뒤 `UnlockRecipe` 결과를 `CraftResult`에 기록(새 해금 여부). `CraftFinished`는 기록 뒤 발생(지금과 같은 순서).

**UI (`BlackSmith.UI`, Game 씬)**
- `CodexPanel`: 상점·저장 패널처럼 열고 닫는다. 7×7 격자(칸 프리팹 또는 씬 오브젝트), 오른쪽 상세 영역, 제목의 진행도. 칸 49개를 넘으면 스크롤이 필요하지만 v2는 49종 고정이라 49칸에 맞춘다(넘으면 경고 로그).
- `GameHUD`: 저장(책) 버튼 옆에 도감 버튼, `OnCodex()`.
- `CraftResultPopup`: 새 해금 줄. 알 수 없는 제작품이면 숙련도 줄 숨김, 판매가 표시.
- `CraftingPanel`: 상태 문구에서 매칭 여부를 드러내지 않는다(비어 있음 / 재료 있음 두 가지).
- 글자 버튼은 `ButtonLabelPress` 규칙을 따른다.

## 튜토리얼과의 관계

- 철 원석 ×1 → 철검은 정확 일치라 흐름은 그대로 동작한다. 첫 제작으로 철검이 해금되므로 결과 팝업에 "새 레시피 해금" 줄이 같이 보인다.
- 튜토리얼 중에도 도감 버튼은 열린다(저장 버튼과 달리 흐름을 깨지 않음. 설계자 판단). 해금한 칸이 없는 상태로 시작한다.
- `Step_04`의 "가장 가까운 제작법" 설명은 정확 일치와 맞지 않는다. 문구는 사용자가 에셋에서 직접 고친다(`Step_04.asset`은 현재 사용자 수정 중으로 보이며 건드리지 않는다).

## 빌더 몫 (설계자 판단으로 정해도 되는 것)

- 클래스·필드·에셋 이름, 패널 내부 오브젝트 구성, 칸 크기·간격(임시값), 격자 칸 생성 방식.
- 정확 일치 동률(같은 구성 레시피 2개) 처리와 경고 문구.
- 해금했지만 숙련도 기록이 없는 레시피(20점 미만 제작)의 상세: 숙련도 0 상태(초급 Lv.1, 0 / 필요 수치, 보너스 +0)로 보인다.
- 알 수 없는 제작품 아이템 데이터의 이름("알 수 없는 제작품")과 설명(임시 문구).
- 결과 팝업에서 새 해금 줄의 정확한 위치(기존 배치 원칙: 겹치지 않고 상자 밖으로 나가지 않음).

## [미정]

- 알 수 없는 제작품 아이콘.
- 도감 패널의 최종 비주얼.
- 튜토리얼 문구.

## 검증

- 컴파일 체크, Title/Game Missing Script 0, 콘솔 경고·오류 없음, ItemDatabase 중복 ID 경고 없음(999 추가).
- `execute_code`: 49개 레시피 각각의 정확한 재료로 매칭 → 자기 자신; 수량 ±1, 재료 하나 추가/누락 → null. 도감 번호 1–49 중복 없음·등급 순서.
- 저장: 메모리에서 `JsonUtility` 왕복. 도감 필드 없는 JSON(숙련도 기록 2개) → 그 2개만 해금, 다시 저장·로드해도 유지. 사용자 슬롯 파일은 건드리지 않는다.
- 플레이 모드(Game): 레시피 조합으로 제작 → 해금·결과 팝업 해금 줄, 같은 레시피 재제작 → 줄 없음. 맞지 않는 조합 → 999 지급, 판매가 50, 숙련도·해금 변화 없음, 제작 패널 문구가 레시피 조합과 같음. 도감 패널 열기, 칸 선택 시 상세, 진행도 수치. 튜토리얼 철검 흐름. 끝나면 플레이 모드 종료.
- 확인하지 못하는 것(보고): 실제 마우스 플레이, 빌드 실행, 최종 모양.
