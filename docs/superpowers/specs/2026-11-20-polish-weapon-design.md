# 연마 미니게임 개정: 무기 위의 흠집 + 숫돌 설계

작성 2026-11-20. 대상: 미니게임 이미지 교체 4단계(`2026-11-20-minigame-art-stage4-design.md`)의 개정. 4단계는 흠집 이미지 한 장만 바꿔서 "단색 판 위의 갈색 얼룩"이 되었는데, 원래 기획은 **무기에 흠집이 있고 숫돌로 갈듯이 문질러 지우는 것**이었다.

## 의도

연마는 "무기의 흠집을 숫돌로 갈아 없애는" 장면으로 보여야 한다. 지금은 규칙(흠집 위에서 누르고 드래그해 지움)은 맞지만 장면이 없어 의미가 전달되지 않는다.

## 목표

- 연마 화면에 **검 이미지**가 보이고, 흠집은 **검 위에만** 생긴다.
- 누르고 드래그하는 동안 **숫돌 도구**가 포인터를 따라다니며 갈아내는 느낌을 준다.
- 흠집이 한 종류의 얼룩이 아니라 **몇 가지 모양**(예: 긁힌 자국, 녹, 찍힌 자국)으로 섞여 보인다.

## 비목표

- 문지르기 규칙·난이도·시간 제한·흠집 개수·흠집 크기·완성도 계산 변경 (`docs/GameDesign.md` §4 수치는 그대로).
- 무기 종류별 이미지 (검 1종으로 시작. 이후 확장 여지만 열어 둔다. 사용자 결정).
- 힛 이펙트(`PolishSparkle`)·효과음 변경, 튜토리얼 문구 변경.
- 판정 정확도를 이미지 픽셀에 맞추는 것(판정은 흠집 중심과 `flawRadius` 원 그대로).

## 안티 목표 (이러면 실패)

- 흠집이 검 밖(배경)에 생긴다. 또는 6개(난이도 10) 중 일부가 검 밖으로 삐져나온다.
- 숫돌이 흠집을 가려서 지워지는 진행이 안 보인다.
- 로직이 이미지·씬 좌표를 알게 된다 (로직은 게임 공간 단위만 안다).
- 기본 설정에서 기존 동작(전체 영역 무작위)이 달라진다.

## 현재 구조 (조사 결과)

- `PolishMinigame.AreaSize` = 16×9 게임 공간, 왼쪽 아래 (0,0). `PlayArea` 1600×900이므로 **1유닛 = 100px**, 중심은 (8, 4.5).
- 흠집은 `PickPosition()`이 `[margin, AreaSize - margin]` 전체에서 무작위로 뽑는다(`margin` 기본 2 → x 2~14, y 2~7). 겹침은 `flawRadius × 2.2`(1.98) 간격으로 30번 재시도 후 포기.
- `flawRadius` 0.9(지름 180px), 개수는 난이도 1에서 3개 → 10에서 6개, 5초 제한.
- 설정 `PolishSettings`는 `CraftingController.polishSettings`로 **Game.unity에 직렬화**된다. 클래스 기본값만 바꿔서는 게임이 바뀌지 않는다.
- 뷰 `PolishMinigameView`: `FlawTemplate` 하나를 복제해 흠집마다 쓰고, 색은 틴트(기본 (0.55,0.25,0.1), 문지르는 중 (0.9,0.45,0.15), 남은 양에 따라 알파 0.25~1). 입력은 `PlayArea`가 받는다.
- 아이템은 검 외에 단검, 도끼, 메이스, 곡괭이, 창, 할버드, 전투도끼, 임시 장비 5종, 알 수 없는 제작품(999)이 있다. 이번에는 모두 같은 검 이미지를 쓴다.

## 접근 방식

| 방식 | 내용 | 장단점 | 결정 |
|---|---|---|---|
| A. 이미지만 교체 | 검 이미지를 깔고 흠집은 그대로 전체에서 생김 | 코드 변경 없음. 흠집이 검 밖에 생김 | 미채택 |
| **B. 생성 영역 설정 + 이미지** | `PolishSettings`에 흠집 생성 영역(게임 공간 Rect)을 추가하고 검 안쪽으로 설정, 뷰에 숫돌·흠집 변형 추가 | 로직은 단위만 알고 이미지는 씬 값으로 맞춤. 기본값이면 기존 동작 | **채택** |
| C. 검의 알파 마스크로 생성 | 이미지 알파에서 위치를 뽑음 | 정확하지만 로직이 이미지를 알게 됨 | 미채택 |

## 설계

### 1. 로직: 흠집 생성 영역 (`BlackSmith.Crafting`)

- `PolishSettings`에 `Rect spawnArea` 추가. 게임 공간 단위, 왼쪽 아래 기준, **흠집 중심이 놓일 수 있는 영역**이다. 기본값은 현재 동작과 같은 `Rect(2, 2, 12, 5)`(x 2~14, y 2~7).
- `PickPosition()`은 `spawnArea`를 쓴다. 영역이 비정상(폭·높이 ≤ 0)이면 기존처럼 `AreaSize * 0.5` 중앙. 기존 `margin` 필드는 **제거하지 않고** 유지하되 이번에는 쓰지 않는다 (직렬화된 씬 값 호환, 제거는 별도 정리).
- 겹침 회피: 첫 번째로 `flawRadius × 2.2` 이상 떨어진 후보를 쓰는 규칙은 그대로이고 난수 사용 순서도 같다. 다만 좁은 영역(검 띠)에서는 30회 재시도로 자리를 못 찾고 마지막 후보를 채택해 흠집이 크게 겹쳤다(측정: 10.3×1.6 영역에서 500번 중 493번 겹침, 최악 거리 0.05). 그래서 **재시도를 400회로 늘리고, 끝까지 못 찾으면 마지막 후보 대신 기존 흠집에서 가장 먼 후보를 쓴다.** 기본 영역은 예전 알고리즘과 씨드 500개·흠집 3000개 모두 위치가 같음을 확인했다(회귀 없음).
- 씬의 `CraftingController.polishSettings.spawnArea`는 검 이미지를 측정한 값으로 설정한다 (자동 기본값은 바뀌지 않으므로 씬에 직접 넣는다).

### 2. 이미지 (gpt-image, 스타일 기준 `heat_bar_frame.png`)

| 이미지 | 용도 | 조건 |
|---|---|---|
| `polish_blade` | 검 전체(손잡이 왼쪽, 끝 오른쪽), 가로 방향 | 투명 배경, 만화풍. **넓고 곧은 날**(두께 약 4.0유닛 = 400px, 날 직선 구간 약 12.5유닛 목표)로 6개 흠집이 들어가게. 측정: 난이도 10 흠집 6개를 원이 겹치지 않게(간격 ≥ 1.8) 두려면 흠집 중심 영역 10.7×2.2(날 12.5×4.0)에서 겹침 1.1%, 최악 거리 1.66. 더 좁으면 겹침이 급증(12.5×3.6은 15%). 날 표면은 밝은 회색 강철(갈색 흠집이 보이게). 손잡이·가드·끝은 날 직선 구간 밖. |
| `polish_flaw_scratch`, `polish_flaw_dent` | 흠집 변형 2종 (기존 `polish_flaw` = 녹 얼룩 1종 재사용) | 흰색/무채색, 외곽선 없음, 원에 가까운 형태로 이미지에 꽉 참 (틴트가 색을 정하므로) |
| `polish_whetstone` | 포인터를 따라다니는 숫돌 | 가로로 긴 직육면체 숫돌(회색 돌, 약간 젖은 느낌), 만화풍 외곽선 허용, 틴트 없음 |

### 3. 뷰 (`PolishMinigameView`, 로직 불변)

- `[SerializeField] Sprite[] flawSprites`: 흠집 인덱스 `i`에 `flawSprites[i % Length]`를 적용(결정적, 로직·난수 불변). 비어 있으면 템플릿 스프라이트 그대로.
- `[SerializeField] RectTransform whetstone`: 포인터를 누르고 있는 동안만 보이고, 드래그 위치를 따라 `PlayArea` 로컬 좌표로 이동한다. `Hide`/끝(`IsFinished`)/뗌에서 숨긴다. `raycastTarget = false`. 접촉면이 포인터에 오도록 pivot을 아래 중앙으로 두어, 문지르는 흠집이 가려지지 않게 한다 (가림 정도는 렌더링으로 확인 후 조정).
- 흠집은 검 위에 그려지고(검 이미지가 아래), 숫돌은 흠집 위, 힛 이펙트(UI 정렬 10) 아래.

### 4. 씬 (Game.unity `PolishPanel`)

- `PlayArea` 배경색을 다른 미니게임과 같은 어두운 반투명(0.08,0.05,0.04,0.55)으로 바꾸고, 자식 `Blade`(검 이미지, 맨 뒤, 가운데)를 추가한다. 위치·크기는 이미지 측정값으로 정한다.
- `CraftingController.polishSettings.spawnArea`를 검의 날 안쪽으로 설정한다: 흠집 중심 y 범위 = 날 두께 − 흠집 지름(1.8), x 범위 = 날 직선 구간 − 흠집 지름. 목표 값은 `Rect(2.65, 3.4, 10.7, 2.2)` (중심 (8, 4.5), 실제는 측정해 정한다).
- `flawSprites`(3종)와 `whetstone` 오브젝트를 연결한다.

### 5. 문서

- `docs/GameDesign.md` §4 연마 행 "사포질하듯" → "숫돌로 갈듯이"로 문구만 수정 (규칙·수치 불변). `PolishMinigame` 클래스 주석의 "사포질하듯"도 같은 문구로 수정.

## 제약

- 문자열·값 중 **미정**으로 표시된 것은 결정하지 않는다 (이번 변경에 해당 없음).
- 씬 저장은 사용자가 요청할 때만. Game 씬은 additive로 열어 작업한다.
- 테스트 어셈블리가 없으므로 로직 검증은 `execute_code`로 한다(씨드를 바꿔가며 흠집 위치가 영역 안인지 확인).

## 판단 (확인 필요)

- 무기는 검 1종, 날은 넓고 곧은 형태(흠집 6개 수용). 
- 흠집 변형 3종(긁힘/녹/찍힘)과 인덱스 기반 선택.
- 숫돌은 누르고 있는 동안만 표시. 숫돌 문지르는 연출(진동·흔들림)은 이번 범위에서 제외(필요하면 후속).
- `margin`은 남겨 두고 쓰지 않는다.
